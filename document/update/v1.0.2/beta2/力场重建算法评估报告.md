## 1. 问题陈述

### 1.1 用户意图

模型表面贴有 Cell（力值采集器），每个 Cell 代表该位置检测到力值。目标是做一个**可视化算法**，把离散的 Cell 力值重建为**连续的力场**，让用户直观感受到力值在模型上的分布效果。

### 1.2 当前效果的问题

用户观察到：v1.0.2 提出的 Method A+B 算法组合中，点云似乎都是从对应传感器位置射出去的**半圆形色斑**。每个 Cell 周围形成一个以传感器为中心的彩色圆盘，而非真正的连续场重建。

### 1.3 用户的期望

参考 Wendland 算法文档（`Wendland压力场重建模型.md`），其核心思想是**从离散采样值反向重建连续场**，而不是从传感器位置向外"发射"力场。当前实现的效果与这一理念不符。

```javascript
// ...

```

该版本中 `getVirtualAnchors` 函数虽然已定义，但**从未被调用**（死代码）。

**v1.0.2 当前实现** 重构为 `reconstructOnDenseGeo` 后，开始调用 `getVirtualAnchors`，将虚拟锚点传入重建函数：

```javascript
const anchors = getVirtualAnchors(activeCells, cellPressures);  // ← 虚拟锚点
```

## 3. 核心缺陷：虚拟锚点系统

### 3.1 虚拟锚点的工作方式

`getVirtualAnchors` 为每个 Cell 生成 13 个锚点：

| 锚点 | 位置 | 压力乘数 | 权重 |
|------|------|---------|------|
| 中心 (×1) | Cell 坐标 | 1.0 | 1.5 |
| 外圈 (×8) | Cell 半径处，等角分布 | 0.8 | 0.8 |
| 中环 (×4) | 半径一半处，等角分布 | 0.45 | 0.5 |

所有锚点的法线均为 Cell 法线，位置在 Cell 切平面上的圆环上。

### 3.2 为什么会产生半圆形效果

Wendland 重建公式为：

$$P(v) = \frac{\sum_i P_i \cdot \varphi(r_i)}{\sum_i \varphi(r_i)} \times \min(1, \sum_i \varphi(r_i))$$

当 $i$ 遍历**虚拟锚点**而非真实 Cell 时，每个 Cell 在其周围制造了一个**压力梯度碟**：

```
Cell 中心: P=1.0  (满压)
外圈:      P=0.8  (80%)
中环:      P=0.45 (45%)
```

Wendland 核在这些锚点间做加权平均时，顶点离 Cell 越近，受到的高压锚点影响越大；越远，低压锚点（0.45×）占主导。结果是一个**以 Cell 为中心、向外衰减的色斑**。

### 3.3 与 Wendland 理念的冲突

Wendland 压力场重建模型文档（`Wendland压力场重建模型.md` §2）明确指出：

> **"每个像素的颜色 = 它周围传感器读数的加权平均，而不是简单叠加。"**
>
> **"物理注释：传感器读数不是'力源'，它们是连续压力场的离散采样。渲染不应该模拟'力从传感器向外扩散'，而应该从采样值反向重建连续场。"**

虚拟锚点系统在三个方面违背了这一原则：

| 违背点 | 说明 |
|--------|------|
| **伪造采样点** | 在真实 Cell 周围凭空制造 12 个"虚拟传感器"，它们并不存在 |
| **伪造压力梯度** | 外圈 0.8×、中环 0.45× — 模拟"力从传感器向外扩散"，与文档理念完全相反 |
| **阻止自然插值** | 当两个 Cell 间距为 50mm，各自制造独立的锚点碟，中间区域的场值由两个碟的外缘决定，而非两个真实采样点的自然插值 |

### 3.4 视觉效果示意

```
正确 (纯 Wendland):                 错误 (虚拟锚点):
                                     
  Cell A (P=0.8)    Cell B (P=0.2)    Cell A           Cell B
  ●─────────────●                     (○○○)─────────(○○○)
       ↕ 自然插值                       半圆形色斑    半圆形色斑
  0.8 ─── 0.5 ─── 0.2                 0.8→0.64→0.36  0.2→0.16→0.09
  (平滑连续场)                         (独立色斑，中心有间隙)
```

## 4. 正确做法：纯 Wendland 加权插值

### 4.1 数学公式

只使用**真实 Cell 位置和压力值**作为采样点：

$$P(v) = \frac{\sum_{c \in \text{Cells}} P_c \cdot \varphi(r_c)}{\sum_{c \in \text{Cells}} \varphi(r_c)} \times \min\!\left(1,\; \sum_{c \in \text{Cells}} \varphi(r_c)\right)$$

其中：
- $P_c$ = Cell $c$ 的实际压力读数
- $r_c = d(v, c) / R$，$d$ 为顶点 $v$ 到 Cell $c$ 的 3D 欧氏距离
- $R$ = 查询半径 (FIELD_R)，约为 Cell 间距的 2 倍
- $\varphi(r) = (1-r)^4(4r+1)$ (Wendland C2 核)

### 4.2 为什么这样做是对的

| 性质 | 说明 |
|------|------|
| **Cell 是采样点，不是力源** | 每个传感器只告诉你"这个位置的压力是 X"，重建算法的任务是用这些离散采样值估计任意位置的连续场 |
| **加权平均消除密度假象** | 分子分母同时包含 $\varphi(r)$，Cell 密集区域不会因为传感器多而变亮 |
| **自然插值** | 两个 Cell 之间的区域，场值从一侧的 $P_A$ 平滑过渡到另一侧的 $P_B$ |
| **边缘渐隐** | $\min(1, \sum\varphi)$ 在覆盖不足处自然衰减到 0 |
| **保界性** | 重建值永远在 $[\min(P_c), \max(P_c)]$ 范围内，不会产生虚假高压 |

### 4.3 仿真验证

在 `仿真/3D压力场重建仿真对比报告.md` 的 3D OBJ 模型实验中，纯 Wendland C2（无虚拟锚点）的结果：

| 指标 | 结果 |
|------|------|
| 重建最大值 | 98.78 (真实上限 100) ✓ |
| 重建最小值 | 0.32 ✓ |
| 局部峰数量 | 与真实压力峰吻合 |
| 超界? | 否 ✓ |

相比之下，MLS 方法超界 8%（产生 108.07 的虚假高压），因为多项式外推不受采样值约束。

### 4.4 关键参数：查询半径 R

纯 Wendland 的效果取决于 R 的选择：

| R 值 | 效果 |
|------|------|
| R < Cell 间距 | Cell 之间出现空洞，场不连续 |
| R ≈ Cell 间距 | Cell 边缘刚好接触，过渡生硬 |
| R ≈ 2× Cell 间距 | 相邻 Cell 影响区有 50% 重叠，平滑过渡 ← **推荐** |
| R > 3× Cell 间距 | 过度平滑，丢失局部细节 |

当前默认 `FIELD_R = 60mm`，对于典型 Cell 间距 20-30mm 的手套/鞋垫模型，R/间距 ≈ 2-3，是合理的。

## 5. 方案对比

### 5.1 三种方案定性对比

| 维度 | 方案 A：当前 (虚拟锚点) | 方案 B：纯 Wendland (推荐) | 方案 C：Graph Laplacian |
|------|----------------------|--------------------------|----------------------|
| 采样点 | 13 个/Cell (伪造) | 1 个/Cell (真实) | 1 个/Cell (真实) |
| 场连续性 | 色斑状，Cell 间可能断裂 | 平滑连续 | 平滑连续 |
| 边缘处理 | 人造圆盘边缘 | 自然渐隐 (min(1,Σφ)) | 全局扩散 (可能泄漏) |
| 保界性 | ✅ (锚点压力≤原值) | ✅ | ✅ |
| 计算量 | 13× Cell 数 | 1× Cell 数 | 稀疏矩阵求解 |
| 稀疏场景 | 单 Cell 仍有色斑 | Cell 间距>R 时出现空洞 | 全局扩散填充空洞 |
| Mesh 适配 | 需要 Cell 法线 | 需要 Cell 法线 | 需要面片拓扑 |
| 视觉效果 | "传感器射出半圆" | "连续力场热力图" | "均匀扩散场" |

### 5.2 仿真定量对比 (2D 合成场景)

以下数据来自 `仿真/3D压力场重建仿真对比报告.md`，纯 Wendland C2（无虚拟锚点）在 5 个场景的表现：

| 场景 | Cell 数 | RMSE | 局部峰数 | Edge Decay | 评价 |
|------|--------|------|---------|------------|------|
| uniform_gaussian | 120 | 7.54 | 1 ✓ | 0.40 | 良好 |
| clustered_gaussian | 100 | 44.41 | 2 | 0.46 | 聚类区弱 |
| uniform_saddle | 100 | 4.26 | 1 ✓ | -0.02 | 优秀 |
| edge_sparse_multi | 58 | 16.41 | 1 ✓ | **0.90** | **边缘最优** |
| sparse_15 | 15 | 56.33 | 2 | 0.39 | 极限稀疏弱 |

**关键发现**：
- **正常场景 (Cell ≥ 20)**：纯 Wendland RMSE < 17，局部峰正确，边缘衰减最优
- **极限稀疏 (Cell < 20)**：固定半径产生空洞 — 此时建议切换到 Graph Laplacian

### 5.3 Graph Laplacian 备选方案

仿真报告中 Graph Laplacian 在 3D Mesh 上的表现：

| 优势 | 劣势 |
|------|------|
| 速度极快 (0.6s vs 20.3s) | 边缘泄漏 (Edge Decay 0.43) |
| 天然利用 Mesh 面片拓扑 | 需要 Mesh 邻接关系 |
| 压力严格保界 | 全局扩散可能过度平滑 |
| 极限稀疏场景最优 | 不适合 2D 平面 |

**建议**：正常场景用纯 Wendland，Cell < 20 时自动降级到 Graph Laplacian。

## 6. 改进方案

### 6.1 核心修改：移除虚拟锚点

**修改 `reconstructOnDenseGeo`**，直接使用真实 Cell 数据：

```javascript
// 修改前 (错误):
function reconstructOnDenseGeo(denseGeo, anchors, fieldRadiusU) {
  buildSpatialBuckets(anchors, fieldRadiusU);
  for (let i = 0; i < nVerts; i++) {
    const nb = queryBucketCells(lx, ly, lz);
    for (const a of nb) {
      num += a.p * w;  // 伪造压力
      den += w;
    }
  }
}

// 修改后 (正确):
function reconstructOnDenseGeo(denseGeo, cells, cellPressures, fieldRadiusU) {
  // 为每个 Cell 构建对象 {x, y, z, p, nx, ny, nz}
  const cellData = cells.map(c => ({
    x: c.x, y: c.y, z: c.z,
    p: cellPressures[c.id] || 0,
    nx: c.nx || 0, ny: c.ny || 0, nz: c.nz || 1,
    id: c.id
  }));
  buildSpatialBuckets(cellData, fieldRadiusU);
  for (let i = 0; i < nVerts; i++) {
    const nb = queryBucketCells(lx, ly, lz);
    for (const c of nb) {
      // 法线兼容性过滤 (保留)
      if (nd < 0.1) continue;
      num += c.p * w;  // 真实 Cell 压力
      den += w;
    }
    scalars[i] = Math.max(0, Math.min(1, num / den));
    coverage[i] = Math.min(1, den * 1.8);
  }
}
```

**删除 `getVirtualAnchors` 函数**，以及 `updateHeatmap` 中对它的调用：

```javascript
// 修改前:
const anchors = getVirtualAnchors(activeCells, cellPressures);
const result = reconstructOnDenseGeo(_denseGeo, anchors, fieldRadiusU);

// 修改后:
const result = reconstructOnDenseGeo(_denseGeo, activeCells, cellPressures, fieldRadiusU);
```

### 6.2 保留的部分

以下 beta4 已验证有效的机制应保留：

| 机制 | 位置 | 保留理由 |
|------|------|---------|
| Wendland C2 核函数 | `wendlandPhi(r)` | 数学正确，C2 光滑，紧支撑 |
| 3D 空间分桶 | `buildSpatialBuckets` + `queryBucketCells` | O(V×k) 替代 O(V×N)，性能必需 |
| 法线兼容性过滤 | `nd < 0.1` | 防止力场穿透到模型背面 |
| Mesh 细分 + Laplacian 平滑 | `buildDenseGeometry` | 消除粗网格面片化 |
| 覆盖度混合 | `blendWithGrey` | 低覆盖度→偏灰，高覆盖度→鲜艳 |
| 点云 ShaderMaterial 位移 | `buildPointCloud` GPU 顶点着色器 | 灰色模型不动 + 点云浮动 |
| 动态 ptScale / 力场阈值 | `updateHeatmap` 参数计算 | 适配不同尺寸模型 |

### 6.3 查询半径 R 的自动适配

纯 Wendland 依赖 R 的选择。建议自动计算：

```javascript
// 计算 Cell 间平均间距
const cellPositions = activeCells.map(c => ({x: c.x, y: c.y, z: c.z}));
let minDist = Infinity;
for (let i = 0; i < cellPositions.length; i++) {
  for (let j = i + 1; j < cellPositions.length; j++) {
    const d = dist3D(cellPositions[i], cellPositions[j]);
    if (d > 0 && d < minDist) minDist = d;
  }
}
// R = 2 × 最近邻间距，保证 50% 重叠
const autoFieldR = minDist * 2;
// 与用户设置的 FIELD_R 取较大值
const effectiveFieldR = Math.max(FIELD_R, u2mm(autoFieldR));
```

### 6.4 稀疏场景降级

当 Cell 数量过少（< 20）或 Cell 间距远大于 R 时，自动切换到 Graph Laplacian：

```javascript
if (activeCells.length < 20 || avgCellSpacing > fieldRadiusU * 1.5) {
  // 降级到 Graph Laplacian (沿 Mesh 面片扩散)
  result = reconstructLaplacian(_denseGeo, activeCells, cellPressures);
} else {
  // 正常 Wendland C2
  result = reconstructOnDenseGeo(_denseGeo, activeCells, cellPressures, fieldRadiusU);
}
```

Graph Laplacian 的 3D Mesh 适配已在 `仿真/mesh_compare.py` 中验证（0.6s 完成 52K 顶点，保界，Min=0）。

## 评估结论

**核心判断**：v1.0.2 Method A+B 的渲染架构（灰色模型 + 点云 ShaderMaterial 位移 + 覆盖度混合 + 细分网格）是正确的，但**重建算法的数据源有根本性错误**。虚拟锚点系统将"从采样值重建连续场"变成了"从传感器位置发射色斑"，与 Wendland 理念背道而驰。

**改进方向**：移除虚拟锚点，回归 beta4 的纯 Wendland 加权插值——只用真实 Cell 位置和压力值作为采样点。这不是推翻 Method A+B，而是修正其数据输入层。渲染管线（点云、ShaderMaterial、覆盖度混合）全部保留。

**预期效果**：修复后，力场将表现为模型表面的连续热力图——高压 Cell 附近颜色鲜艳，低压 Cell 附近颜色偏冷，两个 Cell 之间的区域自然过渡，无 Cell 覆盖处自然渐隐为灰色。不再有以传感器为中心的半圆形色斑。
