# 点云力场渲染结构化设计文档

> **版本**：v1.0.2 / beta3  
> **文档类型**：零上下文设计与维护说明  
> **适用对象**：首次接触本项目的开发、测试和算法人员  
> **核心实现**：`src/3D编辑器原型.html`、`src/main.py`

## 1. 文档目标

本文件独立说明 3D 拟物 Layout 编辑器中“压力力场点云”的完整渲染结构，包括：

1. 离散 Cell 压力如何映射到模型曲面；
2. 为什么传播距离必须使用曲面测地距离，而不能只使用三维直线距离；
3. 如何生成和筛选实际显示的点；
4. 如何避免点全部集中到某个 Cell；
5. 点颜色、可见性和隆起高度分别由什么数据控制；
6. 力场参数如何写入和恢复 `.3dlp`；
7. 修改该系统时必须保持的约束、日志和测试方法。

本文不依赖 beta1、beta2 文档，也不假设读者了解本功能的历史。

## 2. 产品语义

### 2.1 Cell 是什么

Cell 是贴附在三维模型表面的压力采样点。每个 Cell 至少包含：

```json
{
  "id": 0,
  "center_mm": { "x": 0, "y": 0, "z": 0 },
  "normal": { "x": 0, "y": 0, "z": 1 },
  "radius_mm": 10,
  "pressure": 0.5
}
```

字段语义：

| 字段 | 含义 |
|------|------|
| `id` | Cell 唯一标识，也是压力和曲面影响缓存的索引键 |
| `center_mm` | Cell 在模型局部坐标系中的位置，单位为毫米 |
| `normal` | Cell 所在曲面的局部法线方向 |
| `radius_mm` | Cell 自身几何半径，不等于力场传播半径 |
| `pressure` | 压力值，当前规范为 `[0, 1]` |

### 2.2 力场半径是什么

`FIELD_R` 表示压力从 Cell 出发，沿模型曲面允许传播的最大测地距离，单位为毫米。

关键约束：

- 滑块值就是实际传播半径；
- 不得再使用 `Cell 间距 × 3`、`Cell 半径 × 系数` 等规则自动扩大；
- `5mm` 必须意味着沿曲面路径最多传播 `5mm`；
- Cell 自身半径与力场半径是两个独立概念。

当前 UI 范围：

```text
最小值：5mm
最大值：200mm
步长：5mm
```

### 2.3 点云表达什么

点云是力场的可视化载体，不是 Cell 本体，也不是模型原始顶点的直接展示。

每个显示点同时表达三个维度：

| 维度 | 数据来源 |
|------|----------|
| 是否显示 | Wendland 加权重建后的连续场值与可见阈值 |
| 颜色 | 压力场标量 `scalar`，映射到 Jet 色带 |
| 隆起高度 | 压力场标量 × 用户隆起比例 |

因此，高压力 Cell 可以更红、更高，但不应仅仅因为压力高就拥有更多点或更大的几何覆盖面积。

## 3. 总体架构

点云力场由四层组成：

```text
┌──────────────────────────────────────────────┐
│ 1. 工程数据层                               │
│ Cell 坐标、法线、压力、renderConfig         │
└──────────────────────┬───────────────────────┘
                       ↓
┌──────────────────────────────────────────────┐
│ 2. 曲面计算层                               │
│ 网格焊接 → 自适应细分 → 邻接表 → Dijkstra   │
│ → Wendland 权重                             │
└──────────────────────┬───────────────────────┘
                       ↓
┌──────────────────────────────────────────────┐
│ 3. 连续场采样层                             │
│ 加权分子/分母 → 归一化插值 → 覆盖度渐隐      │
│ → 阈值过滤 → visibleMask                    │
└──────────────────────┬───────────────────────┘
                       ↓
┌──────────────────────────────────────────────┐
│ 4. GPU 渲染层                               │
│ BufferGeometry + ShaderMaterial             │
│ 颜色、透明度、法线隆起、圆形点片元           │
└──────────────────────────────────────────────┘
```

主入口为：

```javascript
updateHeatmap()
```

主要函数：

| 函数 | 责任 |
|------|------|
| `buildDenseGeometry` | 生成可用于曲面传播和点云显示的共享顶点网格 |
| `buildVertexAdjacency` | 构建 CSR 顶点邻接表 |
| `buildSurfaceInfluences` | 为每个 Cell 计算限半径曲面影响顶点和 Wendland 权重 |
| `reconstructOnDenseGeo` | 计算 Wendland 加权平均场、覆盖度和连续可见掩码 |
| `buildPointCloud` | 创建 GPU 点云几何与 ShaderMaterial |
| `updatePointCloudAttributes` | 更新压力、颜色和透明度属性 |
| `updateHeatmap` | 管理缓存、网格重建和整条渲染链路 |

## 4. 曲面网格准备

### 4.1 为什么必须焊接顶点

OBJ、STL 或加载器输出的几何可能是非索引三角形，或者虽然存在 `index`，每个三角形仍使用独立顶点。

如果不焊接：

- 每个三角形与相邻三角形没有拓扑连接；
- Dijkstra 只能在一个三角形内传播；
- 日志可能出现 `covered=3`；
- 点云只显示少数点，或者全部集中在最后一个 Cell 周围。

当前处理策略：

1. 新建只保留 `position` 的 `BufferGeometry`；
2. 复制原索引；
3. 无条件调用 `BufferGeometryUtils.mergeVertices`；
4. 重新计算顶点法线。

伪代码：

```javascript
let source = new THREE.BufferGeometry();
source.setAttribute('position', geo.attributes.position.clone());
if (geo.index) source.setIndex(geo.index.clone());
source = BufferGeometryUtils.mergeVertices(source, 1e-5);
source.computeVertexNormals();
```

重要约束：不要因为 `geo.index` 已存在就跳过 `mergeVertices`。存在 index 不代表共享顶点拓扑正确。

### 4.2 自适应细分

小力场半径需要更密集的曲面采样，否则 `5mm` 范围内可能只有几个顶点。

目标边长：

```javascript
targetEdge = max(FIELD_R / 4, 1mm)
```

细分级别根据最大边长决定：

```text
maxEdge > targetEdge × 2.5 → 细分 2 级
maxEdge > targetEdge × 1.2 → 细分 1 级
否则                       → 不细分
```

每个三角形每细分一级会变为四个三角形。顶点数上限用于防止大模型爆内存。

当前上限：

```text
maxVerts = 400000
```

估算时应使用焊接后的共享顶点规模，而不是加载器展开后的三角形顶点总数，否则会错误地把细分级别压到 0。

### 4.3 邻接表

曲面传播使用 CSR 形式的顶点邻接表：

```text
adjacency = [offsets, neighbors]
```

- `offsets[i]`：顶点 `i` 的邻居起始位置；
- `offsets[i + 1]`：顶点 `i` 的邻居结束位置；
- `neighbors`：所有邻接顶点的连续数组。

邻接表仅在密集网格变化时重建。

## 5. 曲面影响计算

### 5.1 为什么不用三维球形距离

三维欧氏距离会把空间上靠近、但曲面路径很远的区域错误连接。例如胸口 Cell 可能直接影响手臂或手肘。

错误模型：

```text
d = |vertex - cell|
d <= R 即认为受影响
```

正确模型：

```text
d_surface = Cell 种子顶点到目标顶点的最短曲面路径长度
d_surface <= FIELD_R 才受影响
```

### 5.2 Cell 种子顶点

每个 Cell 首先在密集网格中寻找最近顶点作为传播种子。

候选顶点必须满足：

```javascript
vertexNormal.dot(cellNormal) >= 0.1
```

这样可以避免种子落到模型背面。

### 5.3 限半径 Dijkstra

从每个 Cell 的种子顶点运行 Dijkstra：

```text
边权 = 相邻顶点之间的三维边长
停止条件 = 累积距离 > fieldRadiusU
```

其中：

```javascript
fieldRadiusU = mm2u(FIELD_R)
```

注意：距离是在网格边上累积，因此是曲面测地距离近似，而不是从 Cell 到目标顶点的直线距离。

### 5.4 方向和折角约束

传播过程中有两级法线过滤。

#### Cell 法线兼容

```javascript
vertexNormal.dot(cellNormal) >= 0.1
```

用于阻止传播到明显背向 Cell 的曲面。

#### 相邻顶点法线兼容

```javascript
currentNormal.dot(nextNormal) >= 0.25
```

用于阻止传播跨越过大的尖角或折边。

### 5.5 Wendland C2 权重

曲面距离归一化：

$$r = \frac{d_{surface}}{R}$$

Wendland C2 核：

$$\phi(r) = (1-r)^4(4r+1), \quad 0 \le r < 1$$

当 $r \ge 1$ 时权重为 0。

每个 Cell 的影响缓存结构：

```javascript
Map<CellId, {
  indices: number[],
  weights: number[]
}>
```

必须使用真实 `Cell.id` 作为键。

严重故障示例：如果构建 `cellData` 时漏掉 `id`，所有 Cell 会写入 `undefined` 键，最后一个 Cell 会覆盖前面的缓存，视觉上表现为所有点集中到最后一个 Cell（例如 #3）。

正确结构：

```javascript
const cellData = cells.map(c => ({
  id: c.id,
  x: c.x,
  y: c.y,
  z: c.z,
  p: cellPressures[c.id] || 0,
  nx: c.nx,
  ny: c.ny,
  nz: c.nz
}));
```

## 6. Wendland 加权场重建

### 6.1 目标语义

Cell 是连续压力场的离散采样点，不是向外发力的点源。对于密集曲面上的任意采样顶点，算法应综合附近所有 Cell 的压力值，而不是把多个 Cell 的贡献直接相加。

直接叠加的错误形式为：

```text
field(v) = Σ(Pc × wc)
```

这种形式会使 Cell 数量较多或影响区重叠的位置无条件增亮，并快速饱和到 1。它表达的是“多个力源叠加”，不是“从离散采样重建连续场”。

### 6.2 加权分子与权重分母

每个 Cell 的测地影响缓存提供顶点索引和 Wendland 权重。重建时先累加两个量：

```javascript
weightedSum[vertex] += pressure[cell] * weight;
weightSum[vertex] += weight;
```

当前代码为节省数组，使用：

```javascript
scalars[vertex] += pressure[cell] * weight;
coverage[vertex] += weight;
```

此时 `scalars` 暂时是加权分子，`coverage` 暂时是权重分母，尚不是最终场值。

### 6.3 Wendland 归一化加权平均

对每个权重和大于零的顶点计算：

$$
\bar P(v)=\frac{\sum_c P_c\phi_c(v)}{\sum_c\phi_c(v)}
$$

对应代码：

```javascript
const weightedAverage = scalars[i] / weightSum;
```

该步骤具有以下性质：

- 多个 Cell 重叠时得到压力值之间的平滑插值；
- 增加相同压力的 Cell 不会让结果无条件翻倍；
- 重建值不会超过参与采样 Cell 的压力范围；
- 不再产生直接叠加导致的高值饱和平台。

### 6.4 为什么还需要覆盖度渐隐

如果最终值只使用 `weightedAverage`，单个 Cell 场景中会出现：

```text
(pressure × weight) / weight = pressure
```

即 Cell 整个支撑半径内部都是近似恒定压力，到半径边界才突然消失。为了保留 Wendland 核从中心到边缘的自然衰减，最终场值还要乘以覆盖度：

$$
P(v)=\bar P(v)\cdot\min\left(1,\sum_c\phi_c(v)\right)
$$

对应代码：

```javascript
const weightedAverage = scalars[i] / weightSum;
scalars[i] = clamp(
  weightedAverage * Math.min(1, weightSum),
  0,
  1
);
coverage[i] = Math.min(1, weightSum);
```

该组合同时实现：

- **多 Cell 区域**：使用归一化加权平均进行连续插值；
- **单 Cell 与外边缘区域**：使用 Wendland 覆盖度自然渐隐；
- **高密度区域**：避免因 Cell 数量多而直接累加变亮；
- **无覆盖区域**：保持为 0，不产生固定蓝色背景点。

### 6.5 完整公式

对曲面采样顶点 $v$：

$$
P(v)=
\begin{cases}
\displaystyle
\frac{\sum_c P_c\phi\!\left(d_c(v)/R\right)}
{\sum_c\phi\!\left(d_c(v)/R\right)}
\cdot
\min\!\left(1,\sum_c\phi\!\left(d_c(v)/R\right)\right),
& \sum_c\phi_c(v)>0 \\
0, & \text{otherwise}
\end{cases}
$$

其中：

- $P_c$：真实 Cell 压力，范围 `[0,1]`；
- $d_c(v)$：Cell 种子顶点到 $v$ 的网格测地距离近似；
- $R$：用户设置的 `FIELD_R`；
- $\phi$：Wendland C2 紧支撑核。

## 7. 连续点云采样与可见性

### 7.1 不再按 Cell 分组

旧方案把每个曲面顶点归属给权重最大的 Cell，再从每个 Cell 的候选点中抽取相同数量。这会把连续场重新切分成以 Cell 为中心的独立点团，视觉上仍像“每个 Cell 在发力”。

当前实现删除以下中间结构：

```text
ownerWeight
ownerCell
candidates
equalCount
```

曲面顶点不再拥有唯一 Cell 归属。一个顶点可以同时由多个 Cell 参与加权，其最终值由第 6 节公式统一决定。

### 7.2 采样点的含义

显示点来自焊接、细分和平滑后的密集曲面网格顶点。每个点是连续重建场上的一个离散显示采样，而不是某个 Cell 的附属点。

处理流程：

```text
密集曲面顶点
→ 收集所有可达 Cell 的 Wendland 权重
→ 计算归一化加权平均
→ 乘覆盖度渐隐
→ 根据最终场值生成 visibleMask
→ GPU 点云显示
```

### 7.3 可见掩码

最终场值达到统一阈值时显示：

```javascript
if (scalars[i] >= forceThreshold) {
  visibleMask[i] = 1;
  covered.push(i);
}
```

当前默认阈值：

```text
forceThreshold = 0.03
```

该阈值只负责隐藏接近零的边缘点和无效点，不参与 Cell 归属，也不限制某个 Cell 必须拥有多少点。

### 7.4 视觉结果

新方案的预期结果：

- 相邻 Cell 之间形成连续压力过渡；
- 重叠区域不因简单求和快速饱和；
- 不再出现按 Cell 切开的点团或 Voronoi 式归属边界；
- 单 Cell 外边缘仍按 Wendland 核平滑衰减；
- 点数由连续场覆盖范围与密集网格采样密度决定，而不是人为固定每个 Cell 的配额。

注意：网格密度仍会影响显示点的空间密度，因此密集网格构建必须保持足够均匀。当前不再为了“每 Cell 点数相等”破坏连续场结构。

## 8. GPU 点云渲染

### 8.1 BufferGeometry 属性

点云几何包含：

| 属性 | 类型 | 用途 |
|------|------|------|
| `position` | `vec3` | 模型曲面基础位置 |
| `aNormal` | `vec3` | 点的曲面法线 |
| `aField` | `float` | 压力场值 |
| `aColor` | `vec3` | Jet 色带颜色 |
| `alpha` | `float` | 点是否可见 |

### 8.2 顶点着色器

核心位移：

```glsl
vec3 displaced = position + aNormal * aField * uBulgeHeight;
```

点大小：

```glsl
gl_PointSize = uPointSize * (uPtScale / -mvPosition.z);
```

`uPtScale` 用于抵消透视缩放，使不同模型尺度下点尺寸较稳定。

### 8.3 片元着色器

不可见点直接丢弃：

```glsl
if (vAlpha < 0.01) discard;
```

把方形 point sprite 裁成圆形：

```glsl
vec2 c = 2.0 * gl_PointCoord - 1.0;
if (dot(c, c) > 1.0) discard;
```

最终颜色：

```glsl
gl_FragColor = vec4(vColor, vAlpha);
```

### 8.4 Jet 色带

压力值 `[0, 1]` 映射为：

```text
DeepBlue → Blue → Cyan → Green → Yellow → Orange → Red
```

零值和未通过可见掩码的点不显示，因此不会出现铺满模型的固定蓝点。

### 8.5 点大小

UI 滑块：

```text
整数范围：1–200
实际值：slider / 1000
实际范围：0.001–0.200
```

默认值：

```text
0.080
```

### 8.6 隆起高度

隆起最大高度不再使用模型对角线固定比例，因为大模型会产生过大的法线位移和明显横向漂移。

当前上限：

```javascript
bulgeMax = mm2u(min(FIELD_R * 0.5, 10mm))
```

实际高度：

```javascript
bulgeHeight = bulgePercent / 100 * bulgeMax
```

压力越高，点沿法线抬升越高。显示范围由加权场与统一阈值共同决定，不再为每个 Cell 人为分配固定点数。

## 9. 缓存和失效规则

### 9.1 可缓存内容

以下内容与压力值无关，可缓存：

- 密集网格；
- 顶点邻接表；
- 每个 Cell 的曲面影响顶点；
- 每个影响顶点的 Wendland 权重；
- 点云 BufferGeometry。

### 9.2 必须失效的场景

以下操作必须清除曲面影响缓存：

| 操作 | 原因 |
|------|------|
| 加载新模型 | 几何和坐标空间变化 |
| 修改力场半径 | Dijkstra 截止距离变化 |
| 移动 Cell | 传播种子和路径变化 |
| 修改 Cell 法线 | 方向过滤变化 |
| 添加或删除 Cell | 影响集合变化 |
| 密集网格重建 | 顶点索引全部变化 |

压力值变化不需要重跑 Dijkstra，只需使用已有权重重新计算标量和颜色。

### 9.3 缓存键

影响缓存键至少应包含：

```text
密集网格顶点数量
力场半径
Cell ID
Cell 坐标
Cell 法线
```

不能只使用 Cell 数量，否则 Cell 移动后会复用错误路径。

## 10. `.3dlp` 参数持久化

### 10.1 文件结构

`.3dlp` 是 ZIP 文件：

```text
project.3dlp
├── project.json
└── model.obj / model.stl / ...
```

### 10.2 renderConfig

预览参数保存在 `project.json`：

```json
{
  "renderConfig": {
    "fieldRadius": 5,
    "pointSize": 80,
    "bulgePercent": 100,
    "ptScale": 10486
  }
}
```

字段：

| 字段 | 含义 | 单位/范围 |
|------|------|-----------|
| `fieldRadius` | 曲面传播半径 | mm，5–200 |
| `pointSize` | 点大小滑块整数值 | 1–200，对应 0.001–0.200 |
| `bulgePercent` | 隆起比例 | 0–200% |
| `ptScale` | 点尺寸透视缩放系数 | 自动计算值 |

### 10.3 保存链路

```text
JS exportCells
→ sendBridge('exportCells', { renderConfig })
→ Python MainWindow._on_export
→ project['renderConfig']
→ ZIP/project.json
```

### 10.4 打开链路

```text
Python MainWindow._open_package
→ 读取 project.json.renderConfig
→ bridge.cmd('loadStl', { renderConfig })
→ JS loadStl
→ 恢复 fieldRadius、pointSize、bulgePercent
```

旧工程若没有 `fieldRadius`：

- 含 Cell 的工程使用保守值 `5mm`；
- 新导入、尚无 Cell 的模型可使用默认值 `60mm`；
- 不再根据 Cell 几何半径自动设置为 `50mm`。

## 11. 已知故障模式与根因

### 11.1 所有点集中在最后一个 Cell

表现：

- #0、#1、#2 没有点；
- 所有点聚集在 #3；
- 其他 Cell 的压力变化不再影响重建结果。

首要检查：`cellData` 是否遗漏 `id`。

根因：

```javascript
influences.set(c.id, ...)
```

当 `c.id` 为 `undefined` 时，所有 Cell 共用同一个 Map 键，最后一个 Cell 覆盖前面的影响缓存。

### 11.2 `covered=3`

根因：网格三角形顶点未焊接，Dijkstra 只能在单个三角形内传播。

修复：无条件按 position 调用 `mergeVertices`。

### 11.3 设置 5mm，实际覆盖几十毫米

根因：实际半径曾使用：

```javascript
max(FIELD_R, cellRadius * 1.2, nearestCellDistance * 3)
```

修复：

```javascript
fieldRadiusU = mm2u(FIELD_R)
```

### 11.4 胸口 Cell 影响到手肘

根因：使用三维球形距离，空间邻近区域被直接命中。

修复：沿网格邻接运行限半径 Dijkstra。

### 11.5 重叠区域快速变红并形成平台

根因：使用 `Σ(pressure × weight)` 直接叠加，重叠 Cell 越多，场值越容易达到上限 1。

修复：使用归一化加权平均并乘覆盖度：

```text
field = Σ(P×w) / Σw × min(1, Σw)
```

### 11.6 点云仍呈现每个 Cell 一团

根因：使用 `ownerCell` 将重叠顶点唯一归属，再按 `equalCount` 为每个 Cell 等量抽点。该显示层会把连续场重新拆成多个独立点团。

修复：删除 Cell 归属和等量抽样；所有密集曲面顶点直接根据最终加权场值生成 `visibleMask`。

### 11.7 固定蓝点铺满模型

根因：所有点 `alpha=1`，零值点仍映射为 Jet 深蓝色。

修复：仅 `visibleMask=1` 且标量为正的点可见。

### 11.8 `Illegal return statement` 与 `window.pyCommand is not a function`

后者通常是前者的连锁结果：模块脚本存在语法错误，导致整个模块未执行，Bridge 函数没有注册。

处理顺序：

1. 优先修复首个 JavaScript SyntaxError；
2. 再检查 `window.pyCommand`；
3. 不要把 `pyCommand` 缺失误判为 Python Bridge 单独故障。

为了兼容旧版 QWebEngine Chromium，复杂循环应使用清晰的多行语句，避免过度压缩的一行箭头函数和难以核对的括号结构。

### 11.9 WebGL `Attribute 0 is disabled`

这是旧 Chromium 的性能警告，不一定导致点云逻辑错误，但会污染日志并降低性能。

排查方向：

- 确认点云几何存在 `position` 属性；
- 确认 `ShaderMaterial.index0AttributeName = 'position'` 在材质创建后设置；
- 线框对象使用 `LineBasicMaterial`，不要给 `LineSegments` 使用 `MeshBasicMaterial`；
- 不要把该警告与 `covered=0` 等算法错误混为一谈。

6. 最后再检查颜色和隆起效果。

## 14. 性能特征

设：

- $V$：密集网格顶点数；
- $E$：网格邻接边数；
- $C$：有效 Cell 数；
- $K$：每个 Cell 在半径内访问的顶点数。

主要开销：

| 阶段 | 复杂度近似 | 缓存策略 |
|------|------------|----------|
| 顶点焊接 | 与顶点数近似线性 | 模型变化时 |
| 网格细分 | 每级三角形约 ×4 | 半径或模型变化时 |
| 邻接表 | $O(V + E)$ | 密集网格变化时 |
| 每 Cell Dijkstra | $O(K \log K)$ | Cell 位置/法线/半径变化时 |
| 标量更新 | $O(CK)$ | 压力变化时 |
| GPU 属性更新 | $O(V)$ | 每次力场刷新 |

模拟压力模式下，压力频繁变化，但 Cell 位置和半径通常不变，因此必须复用曲面 influence 缓存。

## 15. 维护约束

后续修改必须遵守：

1. `Cell.id` 不得在任何中间数据结构中丢失；
2. 力场半径不得静默自动放大；
3. 曲面传播不得退化为三维球形查询；
4. 多 Cell 重叠必须使用归一化加权平均，不得恢复直接求和；
5. 不得使用 Cell 唯一归属或每 Cell 等量抽点破坏连续场；
6. 压力为 0 的点不得以蓝点形式显示；
7. 缓存键必须覆盖 Cell 坐标、法线和半径；
8. `.3dlp` 必须保存并恢复 `renderConfig.fieldRadius`；
9. 复杂 JavaScript 修改后必须在目标 QWebEngine 中检查语法；
10. 出现点云偏移或断层时，先检查测地影响缓存、权重和最终场值，不要优先靠调高阈值掩盖问题。

## 17. 最终设计结论

beta3 点云力场不是“以 Cell 为中心绘制球形色斑”，而是一条严格分层的曲面可视化管线：

```text
真实 Cell 数据
→ 共享顶点密集曲面
→ 限半径测地传播
→ Wendland 距离衰减
→ 多 Cell 归一化加权平均
→ 覆盖度边缘渐隐
→ 连续场阈值采样
→ 压力控制颜色和高度
→ GPU 点云渲染
```

该结构的核心目标是同时保证：

- 范围符合用户设置；
- 不跨曲面错误传播；
- 多 Cell 重叠时形成连续、保界的压力插值；
- 不因 Cell 数量增加而直接叠加饱和；
- 不再通过 Cell 分组制造独立点团；
- 参数可随 `.3dlp` 工程持久化；
- 故障可通过明确日志定位。
