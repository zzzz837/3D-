## 第一轮: 力场数据源模式拆分 (Q1-Q10)

### 工具栏 & 属性面板重构

| 需求 | 方案 |
|------|------|
| 工具栏 | 增加 模拟压力 / 导入数据 按钮，保留 力场预览/放置模式/线框/重置视角/编辑模式 |
| 属性面板 | 新增 `propPressure` 独立输入框；label 改为纯备注；新增"力场设置"组(mode select + 压力范围 + 半径slider) |
| 菜单栏 | 视图菜单新增 模拟压力 / 导入数据 入口 |

### 压力归一化 (方案B: 固定范围)

- `propPressureMin` / `propPressureMax` 输入框，默认 [0, 100]
- `updateHeatmap` 使用 `t = (p - pressureMin) / (pressureMax - pressureMin)` 归一化
- 用户输入 Cell A=10, Cell B=100 → 热力图差异明显

### 压力字段分离

- `propPressure.onchange` → `C[F].pressure = parseFloat(...)`，独立于 label
- `getCellPressures()` 只读 `c.pressure`，不再 fallback 到 label
- `exportCells` / `importCells` / 所有 Cell 加载路径同步更新

### 三种数据源模式

| 模式 | 数据源 | 触发方式 |
|------|--------|---------|
| manual | `C[id].pressure` (用户输入) | `propPressure.onchange` |
| simulated | `updateSimPressures()` (每Cell正弦波) | `toggleSimulate()` |
| real | `_importedField` (JSON导入) | `importFieldJSON()` |

### JSON 导入格式

```json
{"cells":{"0":50,"1":80},"range":[0,100]}
```
- `cells` 必填，key=Cell ID, value=压力值
- `range` 可选，缺失时使用 UI 的 pressureMin/pressureMax

### 模拟压力

- 每Cell独立动态pressure (正弦波, 不同相位/频率/振幅)
- 仅更新 `C[id].pressure`，不直接控制 Mesh 颜色
- 模拟开启 + 预览开启 → 动态热力图
- 模拟关闭 → pressure 停止变化
- 仅预览 → 静态热力图

### 代码清理

- 删除 `importCells` (:706) 重复 `pressure` 键
- 删除 `_recompute` 死代码
- 删除 `_hotspots` 热点漂移逻辑

### 解耦

- 力场预览 只负责显示 → `togglePreview()`
- 模拟压力 只负责动态更新 → `toggleSimulate()`
- 两者完全独立，可单独开关

## 第二轮: 性能优化 (需求1)

### 背景

手套模型 ~150万面，开启力场预览后程序明显变卡。原 `updateHeatmap` 每500ms全量遍历所有顶点：

```
遍历150万顶点 → getX/Y/Z + applyMatrix4 → wpToLocal → queryBuckets → Wendland → setXYZ
```

### 优化方案

| 优化 | 实现 | 效果 |
|------|------|------|
| 手动模式不持续刷新 | `togglePreview` 仅对 simulated 模式设 interval | 手动模式 O(1) 开销 |
| 顶点位置缓存 `_vpos` | Float32Array 一次性缓存150万顶点cell空间坐标 (~18MB) | 省去每帧 matrix multiply |
| Influence Cache (CSR) | `_ioff/_icell/_iwgt` TypedArrays 预存影响关系+Wendland权重 | 省去空间分桶+Wendland计算 |
| 分离重建/着色 | `rebuildFieldCache()` + `applyFieldColors()` | 压力变化时只更新颜色 |

### 架构

```
rebuildFieldCache()  [仅cell/半径/FIELD_R变化时调用 ~2-5s for 150万面]
  → 缓存 _vpos (顶点位置)
  → 构建 Influence Cache (CSR格式)

applyFieldColors()  [手动: 仅压力变化时; 模拟: 每500ms ~100-300ms for 150万面]
  → 遍历顶点 → 读缓存权重 → 加权压力 → jetColor → setXYZ
```

### 缓存失效触发

| 操作 | 失效方式 |
|------|---------|
| Cell 放置/移动/删除 | `invalidateFieldCache()` |
| Cell 导入 | `invalidateFieldCache()` |
| 力场半径变化 | `invalidateFieldCache()` |
| 模型重新加载 | `_vpos=null; invalidateFieldCache()` |
| 压力值变化 | 仅 `updateHeatmap._lastKey=null` (不清缓存) |

### 性能日志

控制台输出 `[perf]` 日志：
- `vertex-local-pos cached XXXms N verts`
- `influence-cache built XXXms N verts M edges`  
- `colors applied XXXms covered X/Y cells`

## 第四轮: 性能二次优化 — 覆盖顶点遍历

### 问题

`applyFieldColors` 仍遍历全部 150万顶点，用 `if(s===e) continue` 跳过未覆盖的 → 依然 150万次 JS 循环/帧

### 修正

清灰职责从每帧移到一次性操作：

| 何时清灰 | 机制 | 频率 |
|----------|------|------|
| `rebuildFieldCache` | 全量清灰 + 构建 `_cv` (覆盖顶点列表) | cell/半径变化时 |
| `invalidateFieldCache` | 全量清灰 | cell变化时 |
| 逐帧 `applyFieldColors` | **不清灰** — 只遍历 `_cv` 着色 | 每500ms(模拟) 或 按需(手动) |

### 数据结构

```
_cv: Uint32Array — 预建的覆盖顶点索引列表 (rebuildFieldCache 时收集)
     ~5-10万 for 150万面模型 (覆盖率 3-7%)
```

### 效果 (150万面模型)

| 指标 | 原来 | 现在 |
|------|------|------|
| applyFieldColors 遍历顶点数 | 150万 | 5-10万 (↓93-97%) |
| 每帧 JS 循环次数 | 150万 | 5-10万 |
| 每帧 Color 对象创建 | 750万 | 25-50万 (↓93%) |
| 模拟模式预计耗时 | 100-300ms | 10-50ms |
