### Q1. 归一化策略

- **问题**: `t = clamp((pressure-0)/(1-0), 0, 1)` (`:582`) 硬编码[0,1]
- **方案A(推荐)**: 自动归一化，扫描所有Cell取min/max，`t = (p-min)/(max-min)` 动态映射。所有Cell同值 → 显示中间色(绿/黄)
- **方案B**: 用户手动定义min/max范围
- **方案C**: 保持[0,1]，不推荐
- **备选**: A默认 + B可选开关
- **风险**: 方案A每帧扫描min/max，开销微小可忽略
- **置信度**: 70%
- **归入原因**: 直接影响热力图视觉效果，需用户拍板
回答：方案B
### Q2. 专用压力输入框 vs 复用标签

- **问题**: `propLabel.onchange` (`:618`) 中 `c.pressure = parseFloat(c.label)||0`，标签和压力绑定。输入"ADC1"→pressure=0；输入"100"→标签="100"
- **建议方案**: 属性面板新增独立 `propPressure` 输入框，标签仅供文本标识
- **备选**: 保持现状，仅靠Q1自动归一化弥补
- **风险**: 需同步修改exportCells(`:705`)、importCells(`:706`)，旧数据pressure字段缺失时fallback到`parseFloat(label)||0`
- **置信度**: 85%
回答：采用专用 propPressure 输入框，label 只作为备注文本：

额外补充要求
1. 当前最重要目标

两个 Cell 输入明显不同的 pressure，例如：

Cell A = 10
Cell B = 100

必须在 Mesh 表面呈现明显差异：

A 弱色
B 强色 / 热色

如果两者看起来差不多，说明 pressure 读取或颜色映射仍然有问题。

2. Cell marker 和 Mesh heatmap 必须共用同一个 pressure

统一数据源：

C[id].pressure

不能出现：

Cell marker 用一个值
Mesh heatmap 用另一个值
label 又解析出第三个值
3. 力场预览不是模拟按钮

“力场预览”只负责显示当前 pressure 对应的 Mesh 热力图。

“模拟压力”才负责动态改变 pressure。

两者必须解耦。



## 新增: 需求1 — 力场预览性能优化

**背景**: 手套模型 149万面，一开力场预览程序明显变卡。每次 `updateHeatmap` 全量遍历顶点 + matrix multiply + Wendland计算导致卡顿。

**已实现**:

| # | 目标 | 方案 |
|---|------|------|
| P1 | 手动压力模式不持续刷新 | `togglePreview` 仅对 simulated 模式设置 interval；手动模式压力变化时直接调用 `updateHeatmap()` |
| P2 | 缓存 vertexLocalPositions | `_vpos` Float32Array 一次性缓存所有顶点在cell空间的坐标，避免每帧 matrix multiply |
| P3 | Influence Cache (CSR格式) | `_ioff/_icell/_iwgt` TypedArrays 预存每个顶点的影响Cell+Wendland权重，cell变化时重建 |
| P4 | 分离重建与着色 | `rebuildFieldCache()` 仅在cell/半径变化时调用；`applyFieldColors()` 快速着色，只更新颜色不重建几何 |
| P5 | 缓存失效策略 | Cell 增删移动、FIELD_R变化 → `invalidateFieldCache()` → 重建；压力值变化 → 仅着色 |
| P6 | 性能调试输出 | `[perf]` 日志输出顶点缓存、影响缓存构建、颜色应用耗时(ms) |
