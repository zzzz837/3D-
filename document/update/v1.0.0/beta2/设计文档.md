## 2. 完整接口契约

### 2.1 Python ↔ JS Bridge 协议

```
Python → JS:  bridge.cmd(name, data)  →  window.pyCommand(name, data)
JS → Python:  console.log("BRIDGE:" + JSON)  →  BridgePage.javaScriptConsoleMessage
```

| `undo/redo` | P→J | 撤销/重做 |

### 2.2 NewProjectDialog 数据结构

```python
# 输入：无（由用户在 Dialog 中填写）
# 输出（get_project_info()）:
{
    "name": str,           # 项目名称（非空）
    "channels": int,       # 传感器通道数（≥1，无上限）
    "model_path": str,     # 模型文件绝对路径
    "unit_mm": float,      # 单位比例（mm/模型单位）
}
```

### 2.3 Project Package 格式 (.3dlp)

```
project.3dlp (ZIP, DEFLATED)
├── project.json     # JSON, UTF-8
└── {model_name}     # 原始模型文件（保持原格式）
```

**project.json 结构**（零上下文可解析）：

```json
{
  "version": "2.0",
  "project_name": "string",
  "created_at": "ISO8601",
  "total_points": 200,
  "unit_mm": 1.0,
  "model_file": "model.stl",
  "cells": [
    {
      "id": 0,
      "center_3d": {"x": 0.0, "y": 0.0, "z": 0.0},
      "normal": {"x": 0.0, "y": 0.0, "z": 1.0},
      "radius_mm": 10.0,
      "width_mm": 20.0,
      "height_mm": 20.0,
      "rotation_deg": 0.0,
      "label": ""
    }
  ]
}
```

### 2.4 多格式模型加载

JS 端根据 `format` 字段选择 Loader：

| format | Loader | 依赖 |
|--------|--------|------|
| `stl` | `STLLoader` | 已有 (`lib/three/examples/jsm/loaders/STLLoader.js`) |
| `obj` | `OBJLoader` | 新增（已在 `src/lib/three/examples/jsm/loaders/OBJLoader.js`） |
| `glb` / `gltf` | `GLTFLoader` | 新增（已在 `src/lib/three/examples/jsm/loaders/GLTFLoader.js`） |
| `stp` / `step` | Python 端 subprocess 转换为 STL → 再发送 JS | `pythonocc-core` in conda env `3d-editor` |

## 3. 修改计划

### 3.1 需求 #0：修复 webview 空白

**症状**：应用启动后仅显示 Python 工具栏，webview 区域完全空白。点击"新建"无反应。  
**根因假设**（需启动测试验证）：
1. HTTP 服务器启动后未就绪即加载 URL（竞态）→ 增加重试或使用 `loadFinished` 信号
2. `find_root()` 在某些运行方式下返回错误路径 → 输出诊断日志
3. Three.js importmap 在 Qt WebEngine 中解析失败 → 增加 JS 错误上报

**修改点**：
- `src/main.py:_init_webview()`：增加 `loadFinished` 诊断 + 失败重试
- `src/3D编辑器原型.html`：增加全局 JS 错误拦截上报到 Bridge
- 确保 HTML → JS 引擎可正常加载

### 3.2 需求 #1：NewProjectDialog

**修改点**：
- `src/main.py`：新增 `NewProjectDialog(QDialog)` 类
  - 字段：项目名称（QLineEdit）、通道数（QSpinBox，≥1）、模型文件（LineEdit + 浏览按钮）、单位比例（QDoubleSpinBox）
  - 验证：名称非空 + 模型文件有效 + 通道数 ≥ 1
  - 输出：`get_project_info()` 返回 dict
- `src/main.py:_new_project()`：改用 Dialog 收集参数后加载

### 3.3 需求 #2：修复模型渲染

**修改点**：
- `src/3D编辑器原型.html` - `loadStl` handler：
  - 确保先清理旧 Cell 再计算包围盒（`C={};CG.remove...` 移到 bbox 前）
  - 确保 `RT.position.set()` 替代 `RT.position.sub()`（避免累积偏移）
  - 增加加载失败时的错误提示

- `src/3D编辑器原型.html` - 新增多格式 Loader 切换逻辑：
  - 根据 `data.format` 选择 Loader
  - OBJ/GLB/GLTF 加载后同样走 bvh + surfaceIndex 流程

### 3.4 需求 #3：ZIP 包保存/打开

**修改点**：
- `src/main.py:_save_package()`：新增方法，创建 .3dlp ZIP 文件
- `src/main.py:_open_package()`：新增方法，解析 .3dlp ZIP 文件
- `src/main.py:_on_export()`：判断后缀 → 调用对应保存方法
- `src/main.py:_open_profile()`：判断后缀 → 调用对应打开方法
- 保持 `.json` 格式向后兼容（嵌入 base64 模型）

### 3.5 需求 #6：多格式支持 (STEP/STP/OBJ/GLB)

**Python 端（STP/STEP 转换）**：
- 创建 `src/stp_converter.py`：使用 `pythonocc-core` 读取 STEP，mesh 化后导出 STL bytes
- `_new_project()` 中：检测格式 → STP/STEP 调用 `stp_converter.convert()` → 得到 STL bytes
- conda 环境 `3d-editor` 配置：`conda create -n 3d-editor python=3.10 pythonocc-core=7.8.1`

**JS 端（OBJ/GLB/GLTF 直接加载）**：
- `src/3D编辑器原型.html` importmap 增加 OBJLoader / GLTFLoader / DRACOLoader
- `loadStl` handler 重命名为通用 `loadModel`，内部根据 format 分支

## 5. 启动测试计划

### 5.1 核心操作路径

1. `python src/main.py` → 窗口启动，Python 工具栏可见 → webview 加载 HTML，显示左侧篮子、3D画布、右侧属性面板、下侧状态栏
2. 点击"新建" → 弹出 Dialog → 填写项目名/通道数/选择 STL → 确定 → 模型在 3D 画布中渲染
3. Ctrl+Click 在模型上放置 Cell → Cell 贴合曲面
4. 点击"保存" → 选择 .3dlp → 文件生成
5. 点击"打开" → 选择刚保存的 .3dlp → 模型 + Cell 完整恢复

### 5.2 通过标准
- 应用无崩溃启动
- webview 不再空白，HTML 完整渲染
- 新建 → 模型渲染正确
- 保存 → 打开 闭环通过
