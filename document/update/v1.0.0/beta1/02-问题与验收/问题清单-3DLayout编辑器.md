### S1. [原 Q1] 3D 模型导入格式范围

- **决策来源**：用户确认
- **问题描述**：当前需求规格仅规划了 STL、OBJ、GLTF/GLB 四种格式。
- **最终方案**：MVP 阶段仅支持 STL + OBJ + GLTF/GLB。不引入 FBX/PLY/STEP/IGES。后续通过"模型预处理工具"或插件机制扩展。
- **自决理由**：(1) 这三种覆盖 80%+ 的鞋垫/CAD 导出场景；(2) FBX 需 Autodesk SDK（C++ 绑定复杂）；(3) PLY 可通过 meshio 桥接但不属主流需求；(4) STEP/IGES 是 NURBS 曲面，需额外三角化引擎。
- **风险预警**：若用户实际模型来源依赖非 MVP 格式，将无法直接导入。
- **置信度**：100%（用户已确认）

### S2. [原 Q2] 多部件 3D 模型处理策略

- **决策来源**：用户确认
- **问题描述**：OBJ/GLTF 可能含多个 mesh/group，Cell 应只放在目标曲面上。
- **最终方案**：(1) 导入后自动检测所有 mesh，取面积最大的 open mesh 作为默认放置曲面；(2) 若检测到多个候选曲面（面积接近），弹出选择对话框让用户单选；(3) 被选中的曲面高亮显示，其余 mesh 灰色线框。
- **自决理由**：自动化 + 用户确认的组合策略在保证效率的同时避免误判。
- **风险预警**：自动选择"面积最大"可能不总是正确，需实际模型样例验证。
- **置信度**：100%（用户已确认）

### S3. [原 Q3] 模型物理单位约定

- **决策来源**：用户确认
- **问题描述**：不同建模软件导出时单位不同，STL 本身不存储单位信息。
- **最终方案**：(1) STL 无物理单位，导入时必须记录 `mm_per_model_unit`；(2) 默认按 1模型单位=1mm 预填，但导入界面必须显示原始包围盒和换算后物理包围盒；(3) 若换算后任一维度 <40mm 或 >1000mm，强制弹出"单位确认"对话框，让用户选择 mm/cm/m/inch/自定义比例；(4) 所有 Cell 宽高、面积、间距和偏移均以真实 mm 存储，渲染时按 `mm_per_model_unit` 转换。
- **自决理由**：STL 文件不带单位，不能把 10mm 直接当作 10 个模型坐标单位使用，否则会造成 Cell 相对模型过大或过小。单位确认 + 统一换算可以确保压力传感器点位按真实物理尺寸布置。
- **风险预警**：2D v1.3 JSON 使用 mm 坐标，3D 需确保单位一致性。
- **置信度**：100%（用户已确认）

### S4. [原 Q4] Cell 旋转自由度

- **决策来源**：用户确认
- **问题描述**：Cell 在曲面上的旋转自由度定义。
- **最终方案**：(1) MVP 仅支持面内旋转（绕曲面法向量），手柄为 Cell 边缘的绿色弧形箭头；(2) Cell 法向量始终与曲面法向量对齐（patch 严格贴合曲面）；(3) 后续可通过属性面板输入 pitch/yaw 角度（高级功能）。
- **自决理由**：传感器 Cell 是柔性材料，贴合曲面后不需要额外法向偏转。降低 MVP 复杂度。
- **风险预警**：不确定实际传感器安装是否需要微调 Cell 局部朝向以对齐布线方向。
- **置信度**：100%（用户已确认）

### S8. [原 Q8] 3D 扩散模型距离计算方式

- **决策来源**：用户确认
- **问题描述**：测地线距离 vs 欧几里得距离。
- **最终方案**：MVP 阶段统一使用 **3D 欧几里得距离** 近似曲面测地线距离。后续可在陡峭曲面上切换 Dijkstra 测地线计算。
- **自决理由**：鞋垫等目标曲面较平坦（无 > 90° 弯折），3D 欧几里得与测地线误差 < 5%，且避免实现三角网格图遍历的复杂度。
- **风险预警**：对于高曲率曲面（如手指关节弯折 > 60°），欧几里得近似误差显著。
- **置信度**：100%（用户已确认）

### S9. [原 Q9] Cell 重叠约束与碰撞检测

- **决策来源**：用户确认
- **问题描述**：Cell 在曲面上放置的重叠判定标准和用户反馈机制。
- **最终方案**：(1) Cell 中心最小间距：`min(width, height) / 2 + 2mm`；(2) 拖拽释放时若违反间距约束，Cell 红色警告闪烁并弹回原位置（不创建 MoveCellCommand）；(3) 属性面板可选关闭"碰撞检测"（高级用户手动精细放置时）。
- **自决理由**：2mm 安全间距确保传感器物理边界清晰分离。
- **风险预警**：曲面上的重叠判定涉及两个曲边四边形相交测试，计算复杂度较高。
- **置信度**：100%（用户已确认）

### S13. 技术栈：PySide6 + QWidgets 容器 + Three.js HTML 3D引擎

- **决策来源**：MainAgent 自决（2026-07-03 修订）
- **问题描述**：初始选择 PyQt6 + QML + QtQuick3D，但 Python 3.13 环境下 PyQt6 存在 DLL 兼容性问题，QtQuick3D API 也不可用。
- **最终方案**：切换到 **PySide6 QMainWindow + QWebEngineView 嵌入 Three.js HTML** 混合架构。Python 端提供桌面容器、文件对话框和 Bridge 层；Three.js HTML 处理全部 3D 渲染和 Cell 交互。
- **决理由**：(1) PySide6 在 Anaconda 环境下原生可用；(2) QtQuick3D 渲染性能不稳定，Three.js WebGL 成熟可靠；(3) 吸取 2D 项目 St1 QSGNode→St2 降级的教训，不做技术赌博；(4) Three.js + BVH 可处理 150 万三角面手套模型。
- **风险预警**：需确保 Three.js 本地 bundle（移除 CDN 依赖）以保证离线运行。
- **置信度**：100%（已验证原型可用）

### S14. 架构：混合架构（Python 桌面容器 + Three.js 3D 引擎 + QML 面板）

- **决策来源**：MainAgent 自决（2026-07-03 修订）

- **最终方案**：混合架构 —— 桌面容器层（Python PySide6 QMainWindow + QWebEngineView）加载 Three.js HTML 3D 引擎。Python 核心层（core/）纯 numpy 无 Qt 依赖，可独立 pytest。Bridge 层通过 QWebChannel Signal/Slot 实现 Python↔JS 双向通信。

- **风险预警**：HTML→Python Bridge 通信延迟需持续监控。

### S15. 支持的 3D 格式：STL (ASCII/Binary) + OBJ + GLTF/GLB

- **决策来源**：MainAgent 自决（经用户通过 S1 确认）
- **问题描述**：MVP 阶段需要支持哪些 3D 模型导入格式。
- **自决方案**：STL (ASCII/Binary) + OBJ + GLTF/GLB。使用 Python 标准库 + `numpy` 实现解析器（不引入 `trimesh` 等重型库）。STL 手动解析二进制格式，OBJ 手动解析顶点/面数据，GLTF 使用 `json` + `struct` 解析。
- **自决理由**：(1) 这三种格式覆盖率最高，且数据结构简单；(2) 2D 版 Stage2 实际交付经验表明：依赖越少，打包和调试越简单；(3) 手动解析比引入库更可控。
- **风险预警**：GLTF 规范较复杂（含 bufferViews、accessors、scene graph），需要精心设计解析器状态机。
- **置信度**：95%

### S17. Cell 默认形状：10mm × 10mm 正方形 patch

- **决策来源**：MainAgent 自决
- **问题描述**：新放置的 Cell 默认尺寸。
- **自决方案**：默认边长参考 2D 编辑器的 10mm，按模型尺寸给出建议值（clamp 10~28mm），正方形约束下宽高始终相等。属性面板提供单一边长字段，用户可手工输入 >0 的任意值。渲染时必须通过 `mm_per_model_unit` 换算为模型坐标单位。

### S24. Cell 拖放方案：自定义拖拽（非 Qt Drag/Drop）

- **决策来源**：MainAgent 自决
- **问题描述**：从篮子拖拽 Cell 到 3D 视口的实现方式。
- **自决方案**：自定义拖拽（MouseArea onPressed → onPositionChanged → onReleased，全局坐标映射到 3D 射线检测），不使用 QML 内置 Drag/Drop。
- **自决理由**：(1) 2D 版 Stage2 已验证此方案解决跨坐标空间精确定位问题；(2) Qt 内置 Drag 在 QML 中无法直接获取 3D 射线命中结果；(3) 自定义方案可控制 3D patch 幽灵渲染。
- **风险预警**：QML MouseArea 到 Python 后端 3D 射线检测的通信延迟需控制在 <16ms。
- **置信度**：95%

### S27. Cell 曲面贴合：细分顶点 (10×10) 双向射线投影

- **决策来源**：MainAgent 自决（2026-07-03）
- **问题描述**：Cell 如何贴合到曲面（手套等复杂弯曲模型）。
- **最终方案**：(1) Cell 渲染网格细分为 10×10 子三角形；(2) 每个细分顶点沿 Cell 法向量正反两个方向各发射一条射线（cast=Cell对角线×3~5）；(3) 选取距离最近命中点，满足：距离 ≤ 1.2×Cell对角线、命中法向与 Cell 中心法向同向；(4) 所有顶点沿局部表面法向向外偏移 0.5mm 防 Z-fighting；(5) 无命中顶点保留切平面原始位置。
- **决理由**：已验证对 150 万面手套模型的高曲率手指区域有效。双向投影确保凹凸区域不会投影失败。
- **置信度**：100%（原型已验证）

### S28. Undo/Redo 实现：JSON 快照方式

- **决策来源**：MainAgent 自决（2026-07-03）
- **问题描述**：Python Command 模式 vs HTML JSON 快照。
- **最终方案**：HTML 原型采用 JSON 快照方式（深度 50 步），保存所有 Cell 的完整状态快照。Undo/Redo 在 JS 侧执行，通过 Bridge 通知 Python 更新 UI。后续可迁移到 Python 端 Command 模式。
- **决理由**：JS 侧实现避免 Python↔JS 复杂状态同步。50 步深度对 200 个 Cell 的编辑操作已足够。
- **风险预警**：JSON 序列化/反序列化开销随 Cell 数量增长（200 Cell × 50 步 = ~10K 步开销，可接受）。
- **置信度**：95%
