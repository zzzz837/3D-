### Q1. 需求 #2 — 工具栏简化方向确认

- **问题描述**：当前界面有三行功能入口：
  - **① Python 工具栏**（`main.py:_init_toolbar`）：新建、打开、保存、另存为、撤销、重做、3D预览、截图PNG、放置、线框、重置（11个按钮）
  - **② HTML 工具栏**（`<div class="toolbar">`）：3D预览、放置模式、线框、重置视角、编辑模式（5个按钮）
  - **③ HTML 菜单栏**（`<div class="menubar">`）：文件（导入/打开/保存/另存为/截图）、编辑（放置/编辑切换/撤销/重做/删除）、视图（3D预览/线框/重置）、工具（碰撞检测/缺口检测）

  三行之间存在大量**功能重复**：3D预览、放置、线框、重置同时出现在①和②中；撤销、重做同时出现在①和③中。

- **建议方案**：
  - **Python 工具栏**：保留文件操作类（新建、打开、保存、另存为）+ 截图PNG（5个按钮）
  - **HTML 工具栏**：保留编辑/视图类（放置、线框、重置、编辑切换、3D预览）（5个按钮）
  - **HTML 菜单栏**：保持完整功能入口，作为高级操作的补充（碰撞检测、缺口检测、删除等）
  - 共从 21 个可点击项精简为 16 个，消除 5 处重复。

- **备选方案**：
  - 方案 A（推荐）：上述分工 —— Python 管文件，HTML 管编辑/视图
  - 方案 B：所有功能合入 HTML 菜单栏，Python 工具栏仅保留"新建/打开/保存/另存为"
  - 方案 C：保持现状不变

- **风险预警**：如果用户习惯操作某个入口，移除可能导致困惑。

- **置信度**：75% — 方案合理但需要用户确认偏好。

- **归入置顶原因**：涉及交互设计选择，三种方案的界面差异大。
回答：采用你的建议方案执行

### Q2. 需求 #4 — 热力图功能范围确认

- **问题描述**：`Wendland压力场重建模型.md` 描述了一套完整的 Wendland C2 核加权平均压力场重建算法（空间分桶 + 可分离 Gaussian 后处理）。当前 HTML 中已有简易的"3D热力图预览"（Jet LUT + sine wave 动画循环），但只是演示性质，不基于真实传感器数据。

- **建议方案**：分两阶段实现：
  - **beta3**：将 Wendland 核函数 $(1-r)^4(4r+1)$ 集成到现有热力图预览中，替换 sine wave demo，用 Cell 的 label（用户可填入传感器读数）作为压力值。Cell label 为空则跳过该 Cell。
  - **后续版本**：支持批量导入传感器读数文件（CSV/JSON），增加参数调节面板（query_radius_mm、post_gaussian_sigma）。

- **备选方案**：
  - 方案 A：beta3 先做核函数替换 + 基础可视化，后续补参数面板和数据导入
  - 方案 B：beta3 一次性做完完整功能（数据导入 + 参数面板 + 核函数 + 后处理）

- **风险预警**：空间分桶 + 逐像素重建需要 Canvas 2D 或 Texture 渲染，可能需额外 CPU 时间。336 点规模可实时，但 200+ Cell 需验证。

- **置信度**：80% — 算法清晰但实现细节（像素级重建 vs GPU shader）需确认。

- **归入置顶原因**：beta3 的范围（只换核函数 vs 完整功能）影响工作量预估。
回答：采用**建议方案**：分两阶段实现，但是需要你在这个部分实现两个功能键的使用：1 模拟状态下，数据的导入是系统自动填充模拟 2 真实传入状态下，用户导入压力值或压强的json，这一部分的功能代码需要单独罗列，后续方便修改，因为后续需要跟其他软件进行匹配，这部分可能需要更改

### Q3. 需求 #0 — STP 导入失败

- **问题描述**：STP/STEP 文件导入时，`stp_converter.py` 依赖 `pythonocc-core`（当前未安装），转换失败后弹出警告对话框 → 返回 → 无模型加载。用户描述为"自动打开新的页面让我导入模型"——实际上是转换失败后无反应，用户重新点击"新建"触发了新对话框。

- **自决方案**：
  1. `pip install pythonocc-core` 到 3d-editor 环境
  2. 修复 frozen 模式下 `stp_converter.py` 路径问题（当前 `__file__` 推算路径与 spec 中数据文件路径不匹配）
  3. 转换失败后不清除 dialog 状态，保持友好提示

- **自决理由**：STP 转换逻辑已有，仅缺少依赖和路径修复。纯技术问题。

- **风险预警**：`pythonocc-core` 体积较大（约 500MB），pip 安装可能耗时。

- **置信度**：95%

### Q5. 需求 #3 — Cell 数字标签缩放比例

- **问题描述**：Cell 上的数值标签（显示的 label 文字）过小，与 Cell 半径不成比例。用户期望调整 Cell 尺寸时数字自动缩放。

- **自决方案**：当前 JS 代码 `getOrCreateLabel()` 中 `spr.scale.set(s,s,1)` 用的 `s = Math.max(mm2u(14), mm2u(radius*1.6))`。将系数从 1.6 改为 **2.5**，确保标签随 radius 线性缩放，且最小不低于 14 模型单位。用户修改 propRadius 时，`addOrUpdateCell` 重建 Cell 会同步更新标签大小。

- **自决理由**：纯数值系数调整，无架构变更。标签比例 = radius × 2.5 = 在 Cell 内部可见且不溢出。

- **置信度**：95%
回答：按照你的建议执行，将系数从 1.6 改为 **2.5**

### Q6. 需求 #2 补充 — 菜单栏"文件"子菜单应移除独立模式调用

- **问题描述**：菜单栏"文件"→"导入模型/打开项目/保存项目/另存为"在 Python 容器模式下点击会显示 `msg('请使用Python工具栏的...)` 提示，不执行实际操作。用户只能通过 Python 工具栏操作。

- **自决方案**：当 `window.pyCommand` 存在（即 Python 容器模式）时，菜单项直接调用 `window.pyCommand()` 触发 Python 端对应方法（如 `window.pyCommand('loadStl', {})` → 触发 Qt 信号），而非仅显示提示。这样菜单栏和 Python 工具栏功能等价。

- **自决理由**：消除用户困惑——"明明菜单有选项为什么点不开"。需在 `BridgePage` 中新增 `pyCommand` 双向信号机制或复用现有 `cmd` 方法通过 `console.log` 回传。

- **置信度**：90%
回答：可以的，按照你的建议执行
