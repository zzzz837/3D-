> **文档日期**: 2026-07-03 | **状态**: 原型开发阶段 — Three.js HTML 原型 + Python 桌面容器已可运行，文档体系对齐修正中

## 一、架构总览（修正后）

### 1.0 实际架构

本编辑器采用**混合架构**，吸取了 2D 项目的关键教训（St1 QSGNode → St2 降级为 QPainter）：

```
┌─ 桌面容器层 (Python + PySide6) ─────────────────────────────┐
│  QMainWindow (QWidgets)  ←─  文件对话框、菜单、快捷键         │
│  ├── QWebEngineView   ←─ 3D 渲染引擎 (Three.js via HTML)     │
│  ├── QQuickWidget(QML) ←─ 2D UI 面板 (篮子/属性/表格等)      │
│  └── QStatusBar       ←─ 状态栏                              │
├─ Bridge 层 (Python ↔ JS) ────────────────────────────────────┤
│  WebBridge (QObject + Signal/Slot)  ←─ 双向通信               │
│  JS 侧: window.pyCommand() / Python 侧: runJavaScript()      │
├─ 3D 引擎层 (Three.js + HTML) ────────────────────────────────┤
│  Three.js r160 + three-mesh-bvh  ←─ 曲面渲染 / 射线检测 / BVH│
│  OrbitControls  ←─ 相机控制                                   │
│  Jet LUT 256 级  ←─ 热力图颜色映射                             │
├─ Python 核心层 (纯 python + numpy) ───────────────────────────┤
│  core/  ←─ CellDefinition3D, SurfaceModel, DeviceLayoutProfile3D│
│  core/  ←─ geometry3d.py (三角面面积/法线/包围盒/点三角形测试)  │
│  core/  ←─ CellBasket3D (Cell ID 池管理)                      │
│  render/  ←─ model_importer.py (STL ASCII/Binary 解析)        │
└─────────────────────────────────────────────────────────────┘
```

**关键决策**: QtQuick3D 在 PySide6/PyQt6 环境下 API 不稳定（Stage2-00 已确认），改用 Three.js via QWebEngineView。这是吸取 2D 教训的直接体现 —— 避免在技术验证不充分的情况下投入大量开发。

## 二、架构传承与改进

### 2.1 混合架构设计

```
┌─ 桌面容器 (Python PySide6) ─────────────────────────────────┐
│  Layer 3b: QMainWindow (系统对话框、菜单栏、快捷键)           │
│  Layer 3a: QWebEngineView ← 加载 3D 引擎 HTML                │
│  Layer 3c: QQuickWidget(QML) ← 2D UI 面板 (可选，当前原型内嵌HTML) │
├─ Bridge 层 ──────────────────────────────────────────────────┤
│  Python: WebBridge (QObject + Signal/Slot)                    │
│     ↕ QWebChannel 双向通信                                    │
│  JS: window.pyCommand(cmd, data) / Python: runJavaScript()   │
├─ 3D 引擎 (HTML + Three.js) ──────────────────────────────────┤
│  Three.js r160: 曲面模型渲染 + Cell patch 渲染 + OrbitControls│
│  three-mesh-bvh: BVH 加速 (150万三角面 < 50ms 射线检测)       │
│  Cell 贴合: 细分顶点 (10×10) 双向射线投影 + Z-fighting 偏移   │
├─ Python 核心层 (纯 Python + numpy) ───────────────────────────┤
│  Layer 1: core/model.py, core/geometry3d.py, core/basket.py  │
│  Layer 2: render/model_importer.py (STL 解析器)               │
│  可脱离 Qt/Three.js 独立 pytest 测试                           │
└──────────────────────────────────────────────────────────────┘
```

- 依赖方向严格单向（JS ↔ Bridge ↔ Python core）
- JSON 快照方式 Undo/Redo（50步深度）
- Python core/ 层纯 numpy，无 Qt/Three.js 依赖
- 单线程架构 (Qt GUI 主线程)

### 2.2 关键改进与教训吸收

| 维度 | 2D 教训 | 3D 改进 |
|------|---------|--------|
| **渲染方案** | St1 设计 QSGNode → St2 降级为 QPainter (复杂度超预期) | 直接采用 Three.js (业界成熟 WebGL 引擎，BVH/Cell贴合开箱即用) |
| **Cell 形状** | 原设计任意多边形 (3-12顶点) → St2 简化为正方形 | 直接定义为正方形 patch，避免过度设计 |
| **SVG 解析** | 原设计 XML 逐元素解析 → St2 改为位图 + marching squares | 3D 无 SVG 需求 (被曲面模型替代) |
| **技术栈绑定** | 过度依赖单一 Qt 渲染方案 | 混合架构：Python 桌面容器 + Web 3D 引擎，互不阻塞 |
| **技术验证** | St1 未验证 QSGNode → St2 被迫降级 | Stage2-00 已验证 QtQuick3D 不可用，直接选用 Three.js |
| **视图布局** | 1280×800, 窗格自适应 | 1440×900 (为 3D 视口提供合理宽高比), 视口最小 600px |

## 五、待用户人工确认的问题

> 以下问题置信度 < 90% 或涉及品牌/产品决策，需人工决定。

### D1. 产品正式名称 ✅ 已决策

- **决策**: 统一使用 **"3D 拟物 Layout 编辑器"** (英文: IrregularShapedLayout)
- **窗口标题**: `IrregularShapedLayout v1.0`（当前）→ 建议改为 `3D 拟物 Layout 编辑器 v1.0`
- **文档内部**: 统一称 "3D Layout 编辑器" 或 "3D 拟物 Layout 编辑器"

### D2. QtQuick3D 可行性验证 ✅ 已决策

- **结论**: QtQuick3D 在 PySide6 环境下经测试不可用（DLL 兼容性问题），**已切换到 Three.js via QWebEngineView 方案**
- **现状**: Three.js HTML 原型已实现完整的 Cell 放置、BVH 加速、曲面贴合、Undo/Redo 等功能
- **后续**: Three.js 库需从 CDN 迁移到本地 bundle，确保离线运行

### D3. 3D 模型测试数据的可用性

- **现状**: 手套模型文件（手套模型.stl）已存在（~150万三角面），可用于开发测试
- **缺失**: 小型测试模型（cube.stl, cube.obj, cube.glb）和鞋垫样例（shoe_sample.stl）尚未提供
- **建议**: (1) 手套模型已可满足当前开发需求；(2) 小型测试模型可用程序化生成

### D4. 2D v1.3 测试文件的可用性

- **现状**: `sample_v13.json` 测试文件**不存在**
- **影响**: Stage4 2D 兼容功能的验收需要此文件
- **建议**: 从 2D 编辑器导出一个含 16 个 Cell 的 JSON 文件

### D5. Cell 旋转的"倾斜手柄"后续版本排期 ✅ 已决策

- **决策**: MVP 仅支持面内旋转。倾斜手柄推迟到后续版本。
- **原型当前**: 面内旋转通过属性面板 `旋转(°)` 字段控制

### D6. 主软件 (TactileSense) 的 3D 配置文件加载接口

- **现状**: 3D 编辑器输出 JSON v2.0，主软件需要能加载 v2.0
- **备选方案**: "降维导出"功能 → 将 3D Cell 投影到 XY 平面输出 v1.3 JSON
- **建议**: 与主软件团队协调，优先实现降维导出方案作为过渡

## 八、产品优化建议 (新增功能提案)

> 以下建议从产品使用体验和实际工作场景出发，供 PM 评估排期。

### 🚀 高优先级 (建议 v3.0 首发后跟进)

| # | 功能 | 用户场景 | 核心价值 |
|---|------|---------|---------|
