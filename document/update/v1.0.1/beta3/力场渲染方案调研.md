# 力场渲染平滑化方案调研

## 问题描述

低面数模型上，力场边缘颜色呈不规则形态（三角形锯齿）。根因：Wendland核在**模型顶点**计算 → GPU在**三角面**上线性插值 → 大三角面插值粗糙。

```
顶点A (r=0.2, 红色) ──线性插值── 顶点B (r=0.8, 蓝色)
     │                                      │
     └── 中间像素应该是平滑曲线过渡 ──┘
     实际：直线过渡，在大三角面上形成明显折线
```

---

## 方案对比

### 方案A：GPU片段着色器（推荐 ★★★）

**原理**：在模型材质的片段着色器中，逐像素计算到cell的距离 → Wendland核 → 热力图颜色。不依赖顶点密度。

```
每像素独立计算: distance(pixel, cell_center) → wendland → heatColor
```

**优点**：
- 完美圆形渐变，任何面数都平滑（水波纹效果）
- 不受模型几何复杂度影响
- 单次绘制，无额外mesh
- 工业标准做法（CAD仿真、医学可视化均用此方案）

**缺点**：
- 需要正确实现GLSL（之前ShaderMaterial失败是因为实现有bug，不是方案本身有问题）
- 需通过 `onBeforeCompile` 注入自定义shader代码
- 最大cell数量受uniform数组限制（WebGL通常支持128-256个uniform）

**改动范围**：修改 `togglePreview` 中模型材质设置 + 新增shader uniform更新函数，替代当前的 `applyFieldColors` + `syncHeatmapShellColors`

**实现难度**：中（核心GLSL约80行）

---

### 方案B：自适应三角细分

**原理**：检测力场覆盖区域的三角面，对过大的三角面进行细分（1→4拆分），增加顶点密度使插值更平滑。

**优点**：
- 保持CPU端顶点着色管线不变
- 细分只在力场覆盖区域，不影响其他部分

**缺点**：
- 细分算法复杂（需要处理T-junction、边界连续性）
- 每次cell移动/力场半径变化需重新细分 → 延迟
- 内存随细分级数指数增长
- 工程界较少使用此方案做实时可视化

**实现难度**：高

---

### 方案C：屏幕空间后处理（Gaussian Blur）

**原理**：将热力图渲染到离屏纹理 → 对该纹理做高斯模糊 → 叠加回场景。

**优点**：
- 平滑效果确定且可控（调节模糊半径）
- 与模型几何完全解耦

**缺点**：
- 需要完整的离屏渲染管线（FBO + ShaderPass）
- 模糊会跨越几何边界（手背的力场可能模糊到手掌）
- 需要深度感知模糊（Bilateral Filter）来保持边缘，复杂度翻倍
- Three.js的后处理栈在QWebEngine (Chromium 83) 上兼容性不确定

**实现难度**：高

---

### 方案D：多Pass顶点颜色平滑（当前方案增强）

**原理**：在现有CPU端基础上，增加更多次邻接平滑（5→10次）、扩大邻接核范围（2-hop neighbors）、使用Laplacian平滑替代均值平滑。

**优点**：
- 改动最小（只改 `smoothScalars` 参数）
- 无新依赖

**缺点**：
- 平滑过度会导致所有颜色趋同（loss of contrast）
- 核心问题（三角面线性插值）未解决
- 低面数模型仍会有锯齿

**实现难度**：低

## 工业方案参考

| 领域 | 常用方案 | 说明 |
|------|---------|------|
| CAD应力仿真 (ANSYS/Abaqus) | GPU Shader (per-fragment) | 节点解通过片段着色器渲染 |
| 医学影像 (3D Slicer) | Texture mapping + GPU Shader | 体数据映射到表面 |
| 游戏后处理 (Unity/Unreal) | Screen-space blur + depth-aware | 全屏后处理栈 |
| Three.js社区 (react-three-fiber) | onBeforeCompile注入自定义shader | 最常用方案 |

**结论**：方案A（GPU片段着色器）是工程界做3D表面标量场可视化的标准方案。

## 推荐方案A实施计划

### 核心思路

不用单独的壳层mesh。直接在**模型自身材质**的片段着色器中注入力场计算：

```
渲染流程：
  模型MeshPhongMaterial
  → onBeforeCompile 注入 fragment shader
  → 片段着色器接收 cell[位置/半径/压力] 数组 (uniform)
  → 逐像素: distance(pixel, cell[i]) → wendland → 叠加 → heatColor
  → 与Phong光照结果混合 → 最终颜色
```

### 关键技术点

1. **坐标空间一致**：cell位置存储在RT局部空间，shader中用 `vLocalPosition = position`（顶点属性），同一空间
2. **多cell叠加**：用 `maxCoverage` 取最大覆盖度，`sumWeightedPressure` 加权累加压力
3. **平滑衰减**：Wendland C²连续核 `(1-r)⁴·(4r+1)` + 多层混合（halo/body/core）
4. **数量限制**：最多128个cell传入shader，超过的分批或只取压力最大的

### 改动文件

仅 `src/3D编辑器原型.html`，修改范围：
- 新增 `installFieldShader()` 函数（替代 `applyFieldColors`）
- 修改 `togglePreview()` 中材质设置
- 修改 `updateHeatmap()` 更新shader uniforms
- 保留壳层(HM)但设为不可见（备用）

### 成功标准

- 低面数模型（<1000面）上力场边缘平滑圆形
- 颜色从中心向外渐变，如水波纹
- 无可见三角面锯齿
