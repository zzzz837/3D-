# 力场渲染优化方案 v2 — 基于失败经验的技术选型

## 背景：已尝试的方案及失败原因

| 方案 | 核心思路 | 失败原因 |
|------|---------|---------|
| Shader演示版 `onBeforeCompile` | 注入PhongMaterial片段着色器，逐像素算Wendland | Chromium 83不支持 `onBeforeCompile`——模型始终黑色 |
| `ShaderMaterial` + `ShaderLib.phong` | 用ShaderLib拼接Phong着色器+手动展开#include | 展开后光照明传不过去——模型全黑 |
| CPU Wendland核（当前） | 模型顶点算Wendland → vertexColors → GPU三角插值 | 低面数模型色带不规则、有锯齿 |

**核心约束**：QWebEngine = Chromium 83（2020年），WebGL 2.0部分API实现不完整。

---

## 候选方案

### 方案1：自写最小ShaderMaterial（推荐 ★★★）

**思路**：不依赖Three.js的ShaderLib、不依赖onBeforeCompile。手写一个极简的ShaderMaterial，包含：
- 顶点着色器：`gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0)`
- 片段着色器：简单Phong光照（环境光+漫反射+镜面高光）+ Wendland核热力图混合

**关键代码框架**：
```glsl
// 顶点着色器 (约5行)
varying vec3 vWorldPos;
varying vec3 vWorldNormal;
void main() {
    vec4 worldPos = modelMatrix * vec4(position, 1.0);
    vWorldPos = worldPos.xyz;
    vWorldNormal = normalize(mat3(modelMatrix) * normal);
    gl_Position = projectionMatrix * viewMatrix * worldPos;
}

// 片段着色器 (约40行)
uniform vec3 uLightDir;
uniform vec3 uAmbient;
uniform vec3 uDiffuseColor;
uniform float uSpecular;

// Cell uniforms
uniform int uCellCount;
uniform vec3 uCellPos[32];
uniform float uCellRadius[32];
uniform float uCellPressure[32];
uniform float uFieldOpacity;

varying vec3 vWorldPos;
varying vec3 vWorldNormal;

void main() {
    // Step 1: 简单Phong光照
    vec3 N = normalize(vWorldNormal);
    vec3 L = normalize(uLightDir);
    float NdotL = max(dot(N, L), 0.0);
    vec3 diffuse = uDiffuseColor * NdotL;
    vec3 specular = uSpecular * pow(max(dot(reflect(-L, N), normalize(-vWorldPos)), 0.0), 32.0);
    vec3 baseColor = uAmbient + diffuse + specular;

    // Step 2: Wendland热力图
    float maxW = 0.0, sumPW = 0.0, sumW = 0.0;
    for (int i = 0; i < 32; i++) {
        if (i >= uCellCount) break;
        float d = length(vWorldPos - uCellPos[i]);
        float r = d / max(uCellRadius[i], 1e-6);
        float w = (r >= 1.0) ? 0.0 : pow(1.0 - r, 4.0) * (4.0 * r + 1.0);
        float p = clamp(uCellPressure[i], 0.0, 1.0);
        maxW = max(maxW, w);
        sumPW += p * w;
        sumW += w;
    }
    float sig = (sumW > 0.0) ? clamp(sumPW / sumW, 0.0, 1.0) : 0.0;
    float alpha = smoothstep(0.01, 0.3, maxW) * uFieldOpacity;

    // Step 3: 混合
    vec3 heat = heatColor(sig);  // 调用热力图颜色函数
    vec3 finalColor = mix(baseColor, heat, alpha);
    gl_FragColor = vec4(finalColor, 1.0);
}
```

**与之前失败方案的差异**：
- ❌ 旧方案：依赖 `T.ShaderLib.phong` + 展开 `#include` → lighting传不过
- ✅ 新方案：手写Phong（约8行GLSL），不依赖任何Three.js内部shader
- ❌ 旧方案：依赖 `T.UniformsUtils.merge` → uniforms兼容问题
- ✅ 新方案：手动声明所有uniform，直接赋值
- ❌ 旧方案：用模型局部坐标 (`vLocalPos = position`)——cell位置需匹配RT局部空间
- ✅ 新方案：用世界坐标 (`vWorldPos = modelMatrix * vec4(position, 1.0)`)——cell位置也转世界坐标，坐标空间明确一致

**优势**：
- 逐像素计算，完美圆形渐变
- 不受模型顶点密度影响
- 单次Draw Call，无额外mesh
- 不依赖Three.js内部API，Chromium 83兼容
- 约50行GLSL，调试可控

**风险**：
- Phong光照简化版可能不如ShaderLib视觉效果丰富（可后续增强）
- 需要**将cell位置从RT局部空间转世界空间**才能让shader使用（关键！）
- uniform数组上限32个（WebGL保证值，实际可更大）

**可行性**：**90%** — 理论无阻塞点，上次失败是ShaderLib+include展开问题，此方案完全绕开。

### 方案2：离屏渲染 + 屏幕空间模糊

**思路**：用Three.js EffectComposer将场景渲染到纹理 → ShaderPass做高斯模糊 → 叠加回场景。

**优势**：
- 平滑效果确定（调节模糊半径）
- Three.js有现成EffectComposer/RenderPass/ShaderPass

**劣势**：
- 模糊不区分几何边界（手背的热力会模糊到手掌）
- 需要深度感知模糊(Bilateral Filter)才能解决，复杂度翻倍
- Three.js后处理栈在Chromium 83兼容性未验证
- 增加一个全屏Pass的GPU开销

**可行性**：**60%** — 基础模糊可行，但跨几何边界是硬伤。

---

### 方案3：壳层高分细分 + CPU Wendland（当前方案的极限增强）

**思路**：当前CPU方案 + 壳层做3-4次tessellate → 顶点密度逼近像素密度。

**优势**：
- 不改变现有架构
- 无兼容性风险

**劣势**：
- 3次tessellate = 64x顶点数，内存和计算时间剧增
- 10万面模型→640万面壳层，不可行
- 即使64x密度，在相机拉近时仍有锯齿

**可行性**：**40%** — 仅在模型面数少、力场半径大时可用。

---

### 方案4：Canvas 2D叠加

**思路**：每个cell在屏幕上投影为圆形 → 在2D Canvas上画径向渐变 → CSS叠加在3D视图上。

**优势**：极简，零WebGL依赖

**劣势**：
- 2D叠加与3D表面不贴合（透视、遮挡全错）
- 仅适合"示意"，不适合"仿真可视化"

**可行性**：**20%** — 不满足项目质量要求。

## 推荐路径

**首选方案1（自写ShaderMaterial）**，分两步实施：

### Step 1: 验证shader管道（红shader测试）
替换模型材质为自写ShaderMaterial，片段着色器输出 `gl_FragColor = vec4(1.0, 0.2, 0.1, 1.0)`（橙色）。
- 如果模型变橙色 → shader管道打通 → 进入Step 2
- 如果模型黑色 → ShaderMaterial创建失败 → 回退分析

### Step 2: 完整实现
将cell数据转为世界坐标传入shader → 实现Phong+Wendland混合。

**关键风险点**：cell位置在RT局部空间，shader用世界坐标。转换方式：
```javascript
// JS端：cell位置转世界坐标
const worldPos = new T.Vector3(c.x, c.y, c.z).applyMatrix4(RT.matrixWorld);
shaderUniforms.uCellPos[i] = worldPos;
```
