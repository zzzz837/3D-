### Q1. “重叠”功能是否保留？
- **问题描述**：需求文档提出删除“旋转”功能，并询问“重叠是什么意思，当前添加的 cell 过近系统会自动提示离得太近，所以重叠功能好像没多大用”。这里存在两种不同含义：
  1. 右侧属性面板 / 状态栏里的“重叠层数/重叠统计”仅用于告警和显示；
  2. 真正的“碰撞检测/过近提示”属于放置时阻止重叠的逻辑。
- **建议方案**：保留“碰撞检测”逻辑（避免 cell 过近），删除“重叠层数/重叠统计”的 UI 展示与相关文案，但不动底层距离校验逻辑。
- **备选方案**：
  - 方案 A：只删 UI 展示，保留底层重叠统计供日志或内部判断使用。
  - 方案 B：连底层重叠统计一起删掉，只保留“过近提示”的即时碰撞检测。
- **风险预警**：如果直接删除全部“重叠”相关逻辑，可能影响已有多选拖拽、预览着色、状态同步中对 `overlap` 字段的依赖。
- **置信度**：80%
- **归入置顶原因**：这里涉及“删除展示”还是“删除逻辑”的产品取舍，后续会影响 UI、状态栏、Bridge `state` 字段、测试预期，需你明确。


回答：保留“碰撞检测”逻辑（避免 cell 过近），删除“重叠层数/重叠统计”的 UI 展示与相关文案，但不动底层距离校验逻辑

### Q2. “曲面”功能具体指哪个入口/按钮？
- **问题描述**：需求写“功能键的‘曲面’没多大用，删掉这部分功能”，但当前主界面并没有一个明确文字叫“曲面”的按钮。现有相关候选可能包括：
  1. 状态栏里的 `曲面: x,y,z mm` 鼠标坐标显示；
  2. 顶部/侧边与曲面贴合、曲面吸附有关的逻辑；
  3. 你口中的某个按钮在当前代码里已改名或并不直接显示为“曲面”。
- **建议方案**：如果你的意思是“鼠标移动时显示曲面坐标”这块，那么建议删除状态栏 `sMouse/topMouse` 的实时曲面坐标显示，以及对应 `mousemove` 中的坐标刷新逻辑。
- **备选方案**：
  - 方案 A：删掉“曲面坐标显示”UI，不动曲面贴合/曲面吸附核心算法。
  - 方案 B：如果你说的是某个特定按钮，请指出截图或按钮中文名，我再精准删除。
- **风险预警**：如果误删成“曲面贴合/吸附”，会影响 cell 放置核心功能。
- **置信度**：55%
- **归入置顶原因**：当前“曲面”指代不明确，误删风险高，需你确认具体入口。



回答：主页面右上角-模型信息中的曲面功能

### Q3. “拖出下一个功能键”具体是哪个按钮？替换成什么新功能？
- **问题描述**：需求写“拖出下一个功能键用处不大，这个地方在考虑一个新的功能键”。当前工具栏/功能键较多（如选中、放置、模拟压力、线框等），但“拖出”并不是当前代码中的明确按钮名，可能是口头描述。
- **建议方案**：请你明确指出：
  1. 要删除的是哪个现有按钮（中文名/位置/截图）；

- **备选方案**：如果暂时没想好新功能，建议本轮先只记录该按钮为“候选删除项”，不动代码，避免误删用户还在用的入口。
- **风险预警**：误删错误按钮会直接影响 beta3 演示路径。
- **置信度**：30%
- **归入置顶原因**：按钮目标和替代功能都不明确，无法安全开发。

## 自决区（≥ 90% 置信，已自决，不阻塞开发）

### Q4. 模型整体透明，背面能看到正面 cell，如何处理？
- **问题描述**：当前模型材质/预览逻辑允许看到背面 cell，影响在背面布局。
- **自决方案**：优先检查模型材质 `side / transparent / opacity / depthWrite / depthTest` 与预览模式材质切换逻辑，默认恢复为不透明正面渲染（FrontSide 或可控 DoubleSide），同时保留线框/预览模式的独立开关。
- **自决理由**：这是一个明确的渲染层问题，现有 three.js 材质链路和我们之前的改动已足够定位与修复，不涉及产品路线分歧。
- **风险预警**：若直接改成 `FrontSide` 可能影响某些必须看背面的模型；需要结合当前“线框/预览”模式判断。
- **置信度**：95%
回答：这里我想的是，在添加cell的时候看不到背面cell的情况，具体怎么实现，由你决定 达到我需求就好



### Q5. 模拟力场半径稍小即停止动态渲染，如何排查？
- **问题描述**：需求指出模拟力场下，半径调小后模型力场动态渲染停止。
- **自决方案**：优先检查 `updateHeatmap / SIM_INTERVAL / FIELD_R / _lastKey / cacheOk` 等缓存与定时器逻辑，重点排查“小半径导致缓存 key 不更新 / 顶点覆盖为空 / 定时器提前退出”这几类问题。
- **自决理由**：这是现有模拟渲染链路中的可定位 bug，属于典型逻辑修复，不需要产品决策。
- **风险预警**：修复时可能牵动预览性能缓存，需要补测试避免引入预览卡顿。
- **置信度**：92%
回答：同意先检查逻辑后执行修改
### Q6. 线框模式第一次点击无反应，如何处理？
- **问题描述**：当前线框按钮需要点击两次以上才生效。
- **自决方案**：检查 `tbWire.onclick` 中首次创建 `W` 后 `visible` 状态切换、首次材质/几何创建时机，以及按钮 active 状态是否与 `W.visible` 同步。
- **自决理由**：这是明确的首次状态同步 bug，可直接在现有逻辑中修复。
- **风险预警**：若线框几何依赖模型尚未准备好，需要增加空模型保护。
- **置信度**：96%
回答：修改
