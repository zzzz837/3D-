# 问题清单 - v1.0.1 / beta4

## 置顶区（待用户确认，阻塞开发）

### Q1. 核心矛盾：需求1(无限cell) vs 需求3(完美圆形) vs 需求4(低内存)

- **问题描述**：三项需求存在技术冲突——
  - CPU顶点色方案：满足无限cell + 低内存，但**无法保证完美圆形**（低面数模型上色带不规则）
  - GPU uniform方案：满足完美圆形 + 低内存，但**上限256cell**（GPU硬件限制），不满足上千cell
  - GPU纹理方案：理论上满足全部4项需求（无限cell + 完美圆 + 低内存 + 无抖动），但需确认Chromium 83是否支持`FloatType`纹理
  - CPU+细分方案：**内存爆炸**（10万面细分2次=160万面），违反需求4

- **建议方案**：**GPU纹理方案** — 用1D浮点纹理传cell数据，shader采样纹理计算力场。无cell数量限制（纹理宽4096，可容纳2000+cell）。之前实现失败是因为改动太多引入bug，这次只改数据传输层（uniform→texture），shader计算逻辑不动。

- **备选方案**：CPU方案 + 模型细分1次（10万→40万面）+ 高斯核 + 多Pass平滑。面数增加但可控，圆形近似度提升但非完美圆。

- **风险预警**：GPU纹理方案依赖`FloatType`纹理，Chromium 83的WebGL 2.0理论上支持但需实测验证。

- **置信度**：80% — 纹理方案在Chromium 83上的兼容性是关键风险点

- **归入置顶原因**：GPU纹理 vs CPU细分是两个完全不同的技术方向，影响开发工作量和最终效果上限。

### Q2. 需求2"水波纹丝滑感"的具体期望？

- **问题描述**：当前GPU方案的热力图已经有逐像素圆形渐变（蓝色→青色→绿色→黄色→红色→白色）。需求提到"水波纹那样的丝滑"，需要确认：
- **问题1**：是需要模拟"多个cell同时振荡时产生类似水面波纹的传播感"（动态效果），还是"单个cell的力场像水面涟漪一样从中心一圈圈向外扩散"（静态渐变增强）？
- **问题2**：力场边界"不要太过明显"——当前GPU方案的alpha过渡已经很平滑（smoothstep 0~0.25），你是指GPU方案还不够平滑，还是指CPU方案的边界问题？

- **置信度**：70% — 对"水波纹"的具体视觉期望不明确

- **归入置顶原因**：渲染效果的视觉期望是主观判断，需用户确认

---

### Q3. 需求4"不占据过多内存"的量化标准？

- **问题描述**：当前GPU方案(256 cell)的内存占用约2MB(壳层几何体)+均匀数组。如果扩展到2000 cell，纹理方案增加约16MB。CPU细分方案(1次)增加壳层几何体约20MB。需要确认可接受的内存上限。

- **建议方案**：内存目标<100MB增量（壳层+纹理+缓存），在此约束下选方案。

- **置信度**：75%

- **归入置顶原因**：内存约束决定了CPU细分能做几次、GPU纹理能开多大
