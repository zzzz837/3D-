# 力场渲染方案技术调研 — beta4

## 需求约束

| 需求 | 约束条件 |
|------|---------|
| 1. 无限cell | 可能上千cell，不能有硬件上限 |
| 2. 水波纹效果 | 中心→外圈丝滑渐变 + 动态振荡时有波纹传播感 |
| 3. 完美圆形 | 任何cell半径都要圆形，不能有不规则/锯齿 |
| 4. 低内存 | 增量不超过50MB |
| 5. 无抖动 | 多cell同时渲染不掉帧 |

---

## 候选方案评估

### 方案A：GPU纹理ShaderMaterial（推荐）

**原理**：用1D Float32纹理替代uniform数组传cell数据。Fragment shader通过`texture2D()`采样读取cell坐标/半径/压力。

```
cell数据 → Float32Array → DataTexture(4096×1, RGBA, FloatType) → sampler2D → shader逐像素计算
```

**可行性分析**：
- FloatType纹理在WebGL 2.0中原生支持（`gl.FLOAT` + `gl.RGBA32F`），Chromium 83具备
- Three.js r160的`T.DataTexture` + `T.FloatType` + `T.RGBAFormat`可直接使用
- 纹理宽度4096可容纳2048个cell（每cell占2像素）
- 内存：2048 cell × 8 floats × 4 bytes ≈ 64KB（纹理）+ 壳层几何体(~20MB) ≈ 20MB ✓
- 此前实现失败原因：一次性改动太多（壳层创建+uniform替换+shader重写+缓存逻辑），引入多个bug
- 本次策略：只改数据传输层（uniform→texture），壳层渲染逻辑不动

| 需求 | 满足度 |
|------|--------|
| 无限cell ✅ | 纹理可容纳2000+cell |
| 完美圆形 ✅ | 逐像素计算，等距天然圆 |
| 低内存 ✅ | ~20MB增量 |
| 无抖动 ✅ | 单次draw call |

**待验证**：Chromium 83的WebGL 2.0是否真的支持FloatType纹理。建议写5行测试代码快速验证。

---

### 方案B：CPU顶点色 + 壳层细分

**原理**：壳层clone模型→tessellate细分→CPU Wendland核在细分壳层顶点算色→GPU三角插值。

**可行性分析**：
- 细分1次(×4面数)：10万面→40万面，顶点密度增加，圆形近似度提升
- 高斯核 + 多Pass平滑进一步柔化
- 内存增量：壳层几何体(细分后约20MB) ✓
- 但**仍不是完美圆形**：三角插值在边缘处有可见锯齿

| 需求 | 满足度 |
|------|--------|
| 无限cell ✅ | CPU无上限 |
| 完美圆形 ⚠️ | 近似圆，非完美 |
| 低内存 ✅ | ~20MB |
| 无抖动 ⚠️ | 细分增加顶点，CPU计算可能卡顿 |

---

### 方案C：Canvas 2D叠加（不推荐）

**原理**：cell投影到屏幕→2D Canvas画径向渐变→CSS叠加到WebGL视图上。

| 需求 | 满足度 |
|------|--------|
| 无限cell ✅ | Canvas画2000个圆没问题 |
| 完美圆形 ⚠️ | 2D圆√ 但不贴合3D曲面 |
| 低内存 ✅ | 极小 |

**致命缺陷**：2D叠加贴在屏幕上，不随3D视角弯曲——手套侧面、曲面转折处完全错位。**不满足项目基本要求**。

---

### 方案D：屏幕空间后处理

**原理**：场景渲染到纹理→屏幕空间shader做热力图→深度掩码控制范围。

| 需求 | 满足度 |
|------|--------|
| 无限cell ✅ | shader中循环 |
| 完美圆形 ⚠️ | 2D圆形，不含3D表面信息 |
| 低内存 ✅ | 两个纹理 ≈ 几MB |

**缺陷**：深度掩码只能粗略判断"是否在模型范围内"，做不到曲面贴合。

---

## 推荐决策路径

```
Step 1: 验证FloatType纹理可用性（5分钟）
  → 创建 DataTexture(FloatType) → 传入shader → sample → 显示颜色
  → 通过：方案A可行，进入Step 2
  → 失败：方案A不可行，回退方案B

Step 2: 实现方案A完整逻辑（仅改数据传输层）
  → 改 uniform uCP[128] → sampler2D uCellTex
  → 改 JS syncHeatmapShellColors → 写Float32Array → tex.needsUpdate
  → 不改其他逻辑

Step 3: 如方案A不可行，启用方案B
  → 壳层tessellate + 高斯核 + 多Pass平滑
```
