### Q1. 降采样实现方式

- **问题**: 需求要求"自动降采样以提升性能"，Three.js SimplifyModifier 未在当前 vendored lib 中。
- **方案A (推荐)**: 下载 Three.js SimplifyModifier.js 放入 `src/lib/three/examples/jsm/modifiers/`，在 JS 端对 loaded geometry 做 decimation，然后对降采样后的 mesh 构建 BVH。降采样后的 mesh 同时用于渲染和 Cell 放置。
- **方案B**: Python 端用 trimesh 做 decimation，输出简化 STL，再传给 JS。优点是不依赖 Three.js addon，缺点是增加 Python 依赖和文件 I/O。
- **风险**:
  - 方案A: SimplifyModifier 对大模型可能较慢（主线程阻塞），但只执行一次
  - 两种方案降采样后的 Cell 放置精度需验证
- **置信度**: 75%
- **归入原因**: 涉及架构决策（JS端 vs Python端），且 SimplifyModifier 需额外下载

### Q2. 降采样参数确认

### Q3. 模拟压力预设 — Pulse 模式具体行为

- **问题**: 需求定义了 3 个预设 (Uniform/Wave/Pulse)，Uniform 和 Wave 比较清晰，Pulse 描述为"局部或若干Cell周期性增强，适合展示局部压力脉冲"，但没有给出量化参数。
- **建议方案**: Pulse 模式下每轮随机选 15% 的 Cell 施以"脉冲包络"——压力 = base + amplitude × sin²(π × t_local)，其中 t_local = (time × pulseFreq + cellPhase) % 1.0。每个脉冲持续约 1-2 秒，脉冲结束后该 Cell 回到 base。不同 Cell 的脉冲周期错开，呈现"这里有脉冲那里没有"的效果。
- **备选**: 固定选 3-5 个"热点"Cell 循环脉冲，更简单但不够自然
- **风险**: Pulse 的实现如果太复杂可能引入性能问题
- **置信度**: 65%
- **归入原因**: 需求对 Pulse 的行为描述较模糊，需用户确认期望效果

### Q4. 模拟压力预设 — 默认预设和 UI

- **备选**: 工具栏加预设切换按钮
- **风险**: UI 面板已较满，需注意布局
- **置信度**: 80%
- **归入原因**: UI 设计需用户确认

### Q5. 帧率控制方式

- **问题**: 需求建议用 `requestAnimationFrame` + 时间控制 20-30FPS，或者 33-50ms timer。
- **建议方案**: 用 `setInterval` 40ms (25FPS) 驱动 `updateSimPressures` + `applyFieldColors`。原因：当前架构用 `setInterval` 已在 beta4 稳定运行；`requestAnimationFrame` 需要引入 throttling 且与页面渲染帧率耦合，增加复杂度。
- **备选**: `requestAnimationFrame` + deltaTime throttling，更精确但实现稍复杂
- **风险**: `setInterval` 在浏览器失焦时可能被降低频率，但桌面 app 通常不会
- **置信度**: 85%
- **归入原因**: 两种方案均可，无强技术优劣，需确认偏好
